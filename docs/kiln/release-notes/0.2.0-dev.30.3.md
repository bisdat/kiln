# Kiln 0.2.0-dev.30.3

EMF mods that react to hits now get them, kiln mode runs many more ShroudForge mods, and EML mods that a ShroudForge server keeps off are named in the log. For mod authors, mod API 0.2.13 adds building input, Steam messages, game textures, using an item for a player, container names, the pointer and drag and drop, and recipe tank water. It also fixes item loss in `Items.Move` and the inventory marks at 1440p and 4K.

**Not checked in a real game yet**, unless an entry says it was lab-tested. Everything passed Kiln's tests. If something looks wrong, tell us on GitHub or Discord with `kiln/logs/launcher.log` or `kiln/logs/kiln.log`.

## Players

- **EMF mods that react to hits get them now.** EMF's `on_hit` and Lua's `emf.on_hit` report every hit the server applies to a creature, player or placed object, after the server's step, as on EMF. This is what Mage Skills' Quick Thinking needed. Fall, shroud, cold and drowning damage aren't reported yet, and changing hits (hit rules) and buffs are still to come. Lab-tested. Thanks to PepegaJedi for the report.
- **Chat history search.** With chat history on, **Ctrl+R** searches your earlier chat lines in the HUD and Social chat. Type to filter, **Ctrl+R** or **Down** for older matches, **Ctrl+Shift+R** or **Up** for newer. **Enter** or **Tab** puts the line into the chat box without sending it, **Esc** gives your draft back. Thanks to bisdat, who wrote it (PR #106).
- **EML mods on a ShroudForge server are no longer silently off.** On a dedicated server that runs ShroudForge, an EML mod needs an `extended.mod.json` with `"enabled": true`, and a mod you unzip yourself has none. `kiln/logs/kiln.log` now names those mods at the start, and `kiln/state/eml.json` says what each one needs. The dedicated-server guide has the file to copy. EML mods in `kiln/eml/mods` don't run in such a start either (ShroudForge reads only its own folder), and the log says so. Thanks to sidelia for the report.
- **A server's Mods page says when a mod talks to other players over Steam.**

- **Clearer loader reports.** `kiln.log` says how many EML mods ShroudForge runs from its folder ("N of M"), with their names. ### Kiln mode

Kiln mode is still a choice in Settings (the ShroudForge card, **Kiln's interpreter**), and Kiln's bundled ShroudForge stays the default. This update gives kiln mode many more of the parts ShroudForge mods use.

**Not checked in a real game yet.** These parts are tested on Kiln's test hosts only. The mods named below are what each part is for, not mods we have run in a game with it. Tell us what you see.

- **Entities and components.** Mods can find entities, read their components and change components the game does not track or save itself, in a world you host (single player included) or on a dedicated server.
- **Attributes.** Mods can read and change attributes, with the game's own formulas (maxima, clamps) applied first. sf-unlimited-flight's "Unlimited Glider Stamina" needs this.
- **World settings.** Mods can read and change the world's settings field by field and put them back when switched off, as SF Survival's "Infinite Weapon Durability" does.
- **The game's loaded resources.** Mods can read the items, recipes and other resources the game has loaded, change their values in a world you host, and find a loaded resource by one of its fields (an item's id, for example), as sf-crafting-essentials' recipe changes do. An entity's template is found too.
- **Template components.** Mods can read and change a component of the template an entity was spawned from, and put it back when switched off, as SF Survival's "No Fall Damage" does.
- **Building cursor and props.** Mods can read your building cursor and find the props of an area with their positions. A prop's scale can be changed where the game allows it.
- **Voxel grid.** Mods can read the voxel grid's size and cell size. Reading and changing voxels is not in kiln mode yet.
- **Mod shortcuts.** A mod's keyboard and mouse shortcuts work in kiln mode now. Change them on Kiln's ShroudForge page.
- **Building for you.** Mods that place or remove blocks for you use Kiln's new building input (below), on game client 26430625 only.
- **Without Kiln's menu**, kiln mode now shows its own "do not save" banner when a mod that keeps data in your saves is off.
- Clearer texts for the mods kiln mode holds back, and why.
- Anything that needs ShroudForge 1.8 stays off.
- Still not in kiln mode: reading and changing voxels, spawning, placing and destroying entities, the game's own functions, and impacts. Those calls answer "unavailable", as ShroudForge's own do. Whether a mod keeps working without them depends on the mod.
- For testers: a small test mod, the kiln-mode probe (`mods/tests/sf-kiln-probe` in Kiln's repository), writes one line per kiln-mode read to `kiln/logs/kiln.log`. [Testing kiln mode](https://github.com/frostdev-ops/kiln/blob/main/docs/kiln/shroudforge-kiln-mode-testing.md) says what to look for.

## Mod authors

The mod API is **0.2.13**. It only adds: nothing was removed or changed.

### C#

- **Building input** (`BuildingInput`, Kiln.Client). Your mod can send the local player's ordinary building input: `Select`, `Place`, `Remove`, `Undo` and `Dismantle`, as if the player pressed the keys. The server still checks permissions, resources, range and placement. A first-class, supported API on game client 26430625. Kiln hooks the game's input only when a mod first uses it, so nothing changes for players without such a mod. One request at a time for the whole game (`Busy` otherwise), and `Ok` means queued, never "built": follow `Request.State`. Not checked in a real game yet. Guide: [Building as the local player](https://github.com/frostdev-ops/kiln/blob/main/docs/kiln/modding/building-input.md).
- **Steam messages** (`SteamMessages`, Kiln.Network). A mod that sets `"steamMessages": true` in its `kiln.mod.json` (`<KilnSteamMessages>true</KilnSteamMessages>` in the project file writes it) can send and receive its own Steam peer-to-peer messages on leased channels, one session-answering lease per process. The opt-in is a declaration for trusted mods, not a sandbox. Not yet tried with real Steam: covered by automated tests only.
- **Game textures** (`GameTexture`, `GamePixelFormat`). Turn the game's texture data into RGBA8 pixels and back: BC1 to BC7, packed, 8 to 64-bit formats, mip chains (`Decode`, `DecodeMip`, `Encode`).
- **Use an item for a player** (`Abilities.UseItem(player, slot)`, server, tick thread). The player uses the consumable in one of their own slots the way the game does from the hotbar: the item's sequence plays, one item is taken at the consume event, and the buff gets the item's own values and time. The answer is an `ItemUseResult` (`Started`, or why not: `NotConsumable`, `EmptySlot`, `Busy`...). Use it rather than `ApplyBuff` for food, whose buff types hold no numbers. Lab-tested (#110, thanks Fuzen777).
- **Container names** (`Items.SetContainerName(container, name)`). Renames a chest or other container through the game's own rename, so the name replicates and saves; `""` clears it. The Rename field's rules apply: at most `Items.ContainerNameMaxChars` (48) characters and `Items.ContainerNameMaxBytes` (64) bytes, no control characters. The task gives `true` when the game took the name. Lab-tested (#112, thanks Fuzen777).
- **The pointer and drag and drop in Kiln windows** (`UiDraw`): `Pointer` (in the overlay's pixels), `ButtonHeld(UiMouseButton)`, `DragSource(kind, payload, preview)` and `DropTarget(kind)`. Kinds are your mod's own, so another mod's target never gets your payload. On an older kiln.ui they answer null or false. Not checked in a real game yet (#113, thanks Fuzen777).
- **Where a slot click was** (`SlotClick.Pointer`): the press's position in the overlay's pixels, the space `UiDraw` draws in (#107, thanks Fuzen777).
- **Tank water for recipes.** A new recipe's `"water": n` now draws water from the station's tank (`"waterCharges"` in a change to a game recipe). In C#: `RecipeDefinition.Water` and `ContentEntry.CraftingWater`. Pack Studio's recipes have **Water from the tank**. The game's old "Water" item (`Food_T1_raw_hydration_Water_Pouch_Filled_DEPRECATED`) is a canteen item that a craft takes from the crafter, never tank water: Pack Studio gives it a note instead of passing it off as tank water, and the new lint **KL408** warns about it, and about water at a station without a tank. Thanks to netjunk for the report.
- **`GameEvents.Each` and `Post` by name are cheap now.** They resolved the event name and rebuilt the event list on every call (about 60 ms each). The name is now looked up once, and new overloads take a `GameType`: `GameEvents.Each(GameType, handler)` and `GameEvents.Post(GameType, fields)` (#114, thanks Fuzen777).
- **Outline an entity** (`Ui.World.Outline(entity, OutlineOptions)`, client only). Lights an entity's model with the game's own highlight, the outline the building cursor draws. `OutlineOptions` has `Color` (gold by default), `Pulse`, `Priority` and `Duration`; the `WorldOutline` you get back has `State`, `Reason` and `Dispose()`, and `Ui.World.ClearOutlines()` ends all of your mod's outlines. Two mod colours show at once (a third shares the nearest), and the game's own highlight comes first unless the player sets `"ui": {"outlines": "mods-first"}` in `kiln.json` (`"off"` turns mods' outlines off). It does not show through walls. Game client 26430625; ask `Ui.World.OutlinesAvailable` first. `Kiln.TestKit` records outlines in `KilnHarness.Outlines`. Not checked in a real game yet (#111, thanks Fuzen777).

### Native

New public members, each appended at the end of its table (check `header.size` before calling):
- **kiln.world:** `named_service_open`, `named_service_snapshot`, `named_service_close`, `named_service_compare_exchange` (offsets 616 to 640), and `ecs_registration` (648) with `KilnEcsRegistrationDetail`; table 656 bytes.
- **kiln.assets:** `loaded_snapshot` (232), `loaded_list` (240), `loaded_scalar_compare_exchange` (248) with `KilnLoadedInfo`; table 256 bytes.
- **kiln.build:** `grid_for_session` (152) with `KilnBuildGridSpec`; table 160 bytes.
- **kiln.client:** `building_input_submit`, `building_input_status`, `building_input_cancel` (56 to 72) with `KilnBuildingInput`; table 80 bytes.
- **kiln.net:** the Steam message members (`steam_status` to `steam_accept`, 128 to 176; table 184 bytes) are in the SDK's headers now, every member but `steam_status` taking its owner first. A native plugin is never admitted to a lease: `steam_open` answers unavailable to it.
- **kiln.abilities:** `item_use` (312); table 320 bytes.
- **kiln.items:** v9, `container_rename` and `rename_status` (feature `items.rename`); table 384 bytes.
- **kiln.ui:** `pointer`, `drag_source` and `drop_target`, a size-guarded tail at byte 1056; table 1080 bytes.
- **kiln.engine gate measurements:** a gate hold now ends at the Scene word's release, and the priority restore is measured on its own (`restore_ns`). `KilnEngineGateStats` grows from 96 to 120 bytes (`restores`, `restore_ns_total`, `restore_ns_max`) and `KilnMutationReply` from 48 to 56. `gate_stats` still takes a 96-byte record. Validated on native Windows (#58, thanks bisdat).
- **kiln.render:** v2, outlines appended after v1's drawing and camera (`outline`, `outline_info`, `outline_remove`, `outline_clear`, `outline_status`; feature `ui.world_outline`); table 152 bytes.

## Fixes

- **`Items.Move` into a player no longer loses items.** A move into a player or NPC without a target slot now lands only in the backpack, never in equipment or on the action bar (unless you pass `MoveOptions.ActionBar`). When nothing fits it answers `NoRoom` and nothing moves, an empty equipment slot as a target is refused (use `Items.Equip`), and a move that left items out of reach is rolled back (#109, thanks Fuzen777).
- **Inventory marks and clicks land on the right slot at every resolution and UI scale.** `Ui.Inventory` marks, clicks, `Hovered` and docked panels were scaled by the wrong size, so at 3840x2160 they sat at twice the slot's position (and off at 1440p, 1280x720 or a larger UI scale). (#107, thanks Fuzen777).
- **Kiln's impact programs come back after a world change.** When a new world's registry sat at the old one's address, Kiln's programs were missing and the next registration of the same program was refused as "registered already" (`ApplyBuff` and `RemoveBuff` too). Registering the same program again now succeeds, so a mod may register at every world start (#108, thanks Fuzen777).
- An interrupted mod update no longer leaves its hidden temporary folder behind: Kiln records it first and removes it at the next update or uninstall. This covers interrupted updates from this version on; folders left by older versions are not touched.

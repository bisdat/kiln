# Kiln 0.2.0-dev.31.27

ShroudForge 1.8 mods whose settings sort their choices into groups, such as Gear Up, can be added again. When Kiln
does refuse a ShroudForge mod, the message names the setting, the field and what ShroudForge expects.

## Players and server admins

- **Gear Up and other ShroudForge 1.8 mods can be added again.** Add mods said "Nothing to add: gear_up: not a
  ShroudForge package Kiln can run: setting priorityPick has invalid metadata". Since 1.8, ShroudForge lets a mod sort
  a setting's choices into groups (a choice's label is then `{ "label": ..., "group": ... }`). Kiln only took plain
  text labels, so it refused such a mod that ShroudForge itself runs. The launcher's Add and Kiln's in-game Mods page
  now take both forms. We could not open Gear Up's own files (Nexus lists none for its archive), so this is the likely
  cause, built from ShroudForge's schema and its own starter mod.
- **Grouped choices in the Mods page.** On Kiln's in-game Mods page (Mods > ShroudForge), a list whose choices have
  groups shows each group as a small heading over its checkboxes. A single choice shows its group in front of the label
  ("Hands: Equipped weapon"). ShroudForge's own Modloader shows the groups as tabs. What you pick is saved as the
  mod's value, as before, never as the label you see.
- **A refusal says what is wrong.** When a mod really breaks ShroudForge's rules, the message now names the setting,
  the field and what ShroudForge expects, instead of "invalid metadata". For example: `ShroudForge would refuse setting
  priorityPick: option "x"'s group must be text of 1 to 60 characters`.
- **Kiln refuses what ShroudForge refuses.** ShroudForge checks a mod's `extended.mod.json` against its own schema
  when it reads the mod. Kiln now refuses the same things, so the launcher no longer adds a mod that ShroudForge would
  then refuse at the game's start: a setting field that ShroudForge does not know, a setting `control` outside its
  list, an `applyAt`, `restartRequired` or `assetPreparation` of the wrong kind, an extra field in `enabledWhen`, and
  a choice label that is empty, longer than 120 characters or has a group longer than 60.
- **Kiln's interpreter still runs ShroudForge 1.7.9 mods only.** If you chose Kiln's interpreter for ShroudForge mods
  (Settings, `"shroudforge": { "backend": "kiln" }`), Gear Up and other 1.8 mods still show "uses ShroudForge 1.8
  features; Kiln runs ShroudForge 1.7.9 packages only" there. Use the default backend (the ShroudForge 1.8.1 that Kiln
  brings) for them.
- **Thanks** to Ezra for the report (Discord #general).

## Modders

- No mod API change: mod API 0.2.26, as in 0.2.0-dev.31.26, and no signature or enum change. The MDK packs are
  0.2.0-dev.31.27.
- **Kiln accepts what ShroudForge accepts, and no more.** Kiln's setting check was compared with `$defs.setting` in
  ShroudForge's 1.7.9 schema and the 1.8.0 and 1.8.1 snapshots, and with read_mod_settings.rs. The only change since
  1.7.9 is the option label: 1 to 120 characters of text, or `{ "label": text, "group": text }` with nothing else in
  it (group 1 to 60 characters, counted as characters, not bytes). `applyAt` stays optional: without it a setting
  applies at a restart, or live when `restartRequired` is false, as in ShroudForge. ShroudForge validates
  `extended.mod.json` against its schema when it reads a package (only unknown top-level fields are let through), and
  the schema closes a setting, so a setting field outside `value`, `label`, `description`, `control`, `applyAt`,
  `restartRequired`, `assetPreparation`, `enabledWhen`, `min`, `max`, `step`, `minLength`, `maxLength` and `options`
  refuses the mod; Kiln now refuses it too (before, the launcher took it and the in-game page read past it).
- **The refusal messages** read `ShroudForge would refuse setting <key>: <what>`, one wording for each field: the
  value's kind, a field a setting may not have, `control`, `applyAt`, `restartRequired`, `assetPreparation`, `applyAt`
  against `restartRequired`, empty options, a list without options, an option key that does not match the value's type,
  an option label or group (its form, its length, a stray field), and an `enabledWhen` that is not exactly a setting
  and an `equals`. Option keys and field names are quoted and cut at 80 characters, values at 60. The launcher, the sfi
  editor and the in-game page say the same.
- **Launcher form.** `settings_schema` puts each choice's label text in `x-kiln-enum-labels` (it held the label object
  for a grouped choice). The groups go in the new `x-kiln-enum-groups`: one entry per choice, null for an ungrouped
  one, present only when some choice has a group. The launcher's own form does not use either yet. kiln-manage adds
  `shroudforge::option_label`, `option_group`, `SETTING_FIELDS` and `CONTROLS`.
- **What the in-game page does not use.** The page reads past `presets`, `inputReservations`, tab groups
  (`tab: true`) and `assetPreparation`, and leaves them as they are in `extended.mod.json`. kiln.log says so once per
  package: `ShroudForge mod <id>: Kiln's Mods page does not use presets, inputReservations, ...`. Picking a preset on
  Kiln's page does not change the settings it controls; ShroudForge's own Modloader does that.
- **sfi package model, 1.8 dialect.** It reads the `community-discord` and `video-youtube` links that ShroudForge
  1.8.1 added to its link list. ShroudForge's starter mod has both. The 1.7.9 dialect still refuses them.
- **Kiln's interpreter stays on the 1.7.9 dialect.** A package that only the 1.8 schema accepts, grouped labels
  included, is held as "requires 1.8" in kiln mode. Its manifest says nothing about the 1.8 runtime calls its code may
  make, so Kiln does not run it under 1.7.9 rules.
- The shared fixtures (`schema/fixtures/shroudforge/cases.json`, now 96 cases, run by the launcher, the sfi editor and
  the in-game page) include a setting shaped like Gear Up's priorityPick, ShroudForge's own starter mod
  (`docs/examples/starter-mod`) byte for byte, and labels at the length limits in CJK characters and emoji. Every case
  the fixtures mark refused is also refused by the sfi strict model, which checks ShroudForge's whole schema.

## Not yet seen in a real game

- Gear Up itself has not been added or run: its archive's file list is not on Nexus, and nobody here has downloaded it.
  If priorityPick has another shape, the new message says which field it is.
- The group headings and the "Group: Label" combo items on the in-game page were checked against Kiln's fake UI in
  tests, not drawn in a game.

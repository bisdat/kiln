## Players and server admins

- **EML mods no longer all fail because the game was still closing.** On one start, all of sosmic's EML mods failed with `could not copy enshrouded.kfc.bak ... (os error 32)`. Another program still had Kiln's backup of the game data open: most likely the game he had just quit was still closing, or an antivirus or backup program was reading the file. Kiln now waits for such a file and tries again, for about 2.5 seconds at most. If the file is still in use after that, the reason in the Kiln menu and in kiln.log is one plain sentence: "another program has enshrouded.kfc.bak open (the game still closing, an antivirus or a backup); try again in a moment". That start runs without the EML mods, as before, and the next start tries again.
- **"Open shroudtopia.json" in a Shroudtopia mod's Settings window.** In the launcher, Mods, then a mod's More menu, then Settings: the window has a button that shows `shroudtopia.json` selected in its folder. This is the file of the profile you are looking at, the one Shroudtopia reads. Until the file exists, a line says so instead. Shroudtopia writes the file at the first start with that profile, and the launcher writes it when you change a setting in the window.
- **"Open extended.mod.json" for a ShroudForge mod,** in the same window. It opens the copy in the game's mods folder that ShroudForge runs (Kiln's copy, or your own folder of the mod), never the copy in Kiln's Library. While the profile is not the one the game uses, there is no copy to open, and a line says so.
- **Thanks to sosmic** for the report and the support report zip.

## Modders

- No mod API change: mod API 0.2.26.
- **kiln-eml tries again on a file in use.** The vanilla backup and stage copies, the publication and restore copies, and the renames that set an old backup pair aside are tried again on Windows' sharing violation (os error 32) and lock violation (33) only. The pauses are 0.1, 0.2, 0.4, 0.8 and 1 s, so a file gets six tries in about 2.5 s. When the file is still held, the run's `error` and `reason` in `kiln/state/eml.json` are the plain sentence. A kiln.log warning before it gives the paths, the number of tries and the system's own words. Windows refuses a rename over a target that another program holds with `Access is denied (os error 5)`, and that error is not retried. Host tests use an injected copy function. A Windows test holds a real file without sharing it.
- **`EngineSettings.openFile`** (`engine_settings_get` / `engine_settings_set`; docs/kiln/launcher/contracts.md) is the settings file the engine reads, once it exists: Shroudtopia's `<configDir>/shroudtopia/shroudtopia.json`, and ShroudForge's `extended.mod.json` only in the game's mods folder. It is absent otherwise.

## Not yet seen in a real game

- The wait for a file in use has run against a real file held without sharing on Windows, in a host test, but not in a real start with the game closing or an antivirus holding the backup.
- The Open buttons are covered by unit and browser tests on the launcher's mock backend. On a real install they use the same command as the launcher's other Open folder buttons.

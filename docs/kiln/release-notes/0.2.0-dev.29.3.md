# Kiln 0.2.0-dev.29.3

A patch for 0.2.0-dev.29.2: autosaves no longer hitch on a hard drive, one key press counts once, Quick Deposit's keys work under Kiln, Shroudlink's K tab works beside Auto Doors, a mod's own log no longer shows as a change, and Kiln's overlay comes back after a frame-generation mod is removed. The SDK stays at 0.2.0-dev.29. Everything else is as in 0.2.0-dev.29.2.

## Fixed

- **The last autosave hitches on hard drives.** On a hard drive a hosted world or a server could still stop for a few seconds at an autosave in 0.2.0-dev.29, while Kiln.Saves wrote, confirmed and tidied up its small mod data files (GitHub issue #39, HadToRegister). Kiln.Saves now does all of that file work on its own thread, so the world keeps running while the drive catches up. The game's own write of the world file waits for Kiln's file, at most 6 seconds, so after a crash your mods' data still matches the world it loads; on a drive slower than that the world write goes ahead and `kiln.log` says so. `kiln.log` now says how long each part of a save took and on which thread.
- **One key press counts once, also when the game loses the keyboard focus for a moment.** A key held while the game lost and got back the focus could count as a second press, so a mod's window (for example Kiln Auto Loot's settings on F8) opened and closed again at once. A key's press now counts again only after Kiln saw it released, or after the key's repeat window. Two cases around switching windows remain: a key held away from the game for longer than about 1.5 seconds can count as a new press when you come back, and a key let go while away and pressed again within that time can be missed. If one press still acts twice, `kiln.log` has a line "ui: key … went down again … ms after its last press"; please send it.
- **A key's release reaches a mod also while a text field has the focus.** A mod's key binding could stay down when its window put the focus in a text field before you let the key go.
- **Quick Deposit's keys (G G, K) work when Kiln runs Greeneye's mods.** Kiln's Greeneye host looked for a mod's game functions in the game's code as it was after other loaders had hooked it, so a hook over the function Quick Deposit looks for made it start without its keys. Greeneye mods now find their functions in the game's original code, read from the game's exe, and still get the live addresses; when the exe cannot be read, Kiln looks in the live code as before. `kiln.log` has one line per Quick Deposit start that says whether both of its hooks were found.
- **Shroudlink's K tab works beside Auto Doors.** Auto Doors 1.1.0 hooks the game function the Shroudlink client addon looks for to draw its tab, and it could get there first. Kiln now lets the addon finish looking before it starts early native mods such as Auto Doors (at most 10 seconds, and only when the addon is installed).
- **A mod that writes its own log beside its DLL no longer shows "Changed on disk".** Item Skill Descriptions (and other DLL mods that keep a log in their own folder) made its Library entry read "Changed on disk" after the first game start. A new DLL, script or manifest in the folder still counts as a change, and copy mode and server sync keep the mod's log.
- **Kiln's overlay comes back after you remove a frame-generation mod.** When a game start with a frame-generation (Streamline) or other graphics wrapper crashed, Kiln kept its overlay's drawing off at later starts, as meant; removing the wrapper should have let it try again, but did not always, so the overlay stayed off until `kiln/state/overlay-start.guard` was deleted by hand. Adding, removing or replacing a graphics wrapper now always allows a new try, and a guard left by an earlier Kiln is cleared once at the first start with this version.

## Mod authors

- 0.2.0-dev.29.3 ships the launcher and the runtime only; keep using the 0.2.0-dev.29 SDK (mod API 0.2.4).
- A `KeyBinding`'s `OnPress` (and a native `subscribe_key` subscriber's press, `repeat` 0) no longer comes twice for one press when a focus change falls between the key's raw input and its key message; a held key's repeats after a focus change come with `repeat` 1.
- New in the runtime for native plugins: the core service `kiln.log` v1 (when the game logged the line a log subscriber is handed) and, in `kiln.saves` v1, the appended `stage_progress` entry with the feature bit `KILN_SAVES_CAN_STAGE_BARRIER`. Their headers come with the next SDK.

# Kiln 0.2.0-dev.31.next: a ShroudForge mod the Kiln menu filed under EML

Some ShroudForge mods showed up twice in the Kiln menu, once under EML with only "Loaded" and once under ShroudForge, and the EML row had no switch and no settings. Such a mod is now one row under ShroudForge, with its switch and settings. Settings written in Chinese, Japanese or Korean no longer show as `????` in an English game.

## Players and server admins

- **A ShroudForge mod is one row under ShroudForge, with its switch and settings.** Mineral Production Boxes (Nexus 347) was listed under EML with only "Loaded", and usually under ShroudForge as well, so its whitelist of 30 resources, the refill interval and the target stock could look out of reach. This happened to any mod that ShroudForge runs from its mods folder while Kiln also counts it as an EML mod: a mod whose ShroudForge settings file calls it an EML package (Mineral Production Boxes; Wardrobe - Transmog ships its settings the same way), and any EML mod that needs ShroudForge's runtime (Endless Chests, Quiver and Spellbook). Kiln's launcher adds those to your profile twice, under EML and under ShroudForge. The Kiln menu (Insert, Mods) now lists each of them once, under ShroudForge, and shows what ShroudForge says about it. This works when Kiln runs ShroudForge for you, when your own ShroudForge install runs it, and with Kiln's own ShroudForge interpreter, both before and after a save loads. Plain EML mods stay under EML.
- **Your settings are where they were.** The Kiln menu and ShroudForge's own Modloader window change the same file in the mod's folder. Ticks you already made in ShroudForge's window stay.
- **When only EML runs such a mod, the menu says so.** If no ShroudForge runs it (Kiln's EML loader alone, or EML's own loader in the game folder), the mod stays under EML. Its row then says that its ShroudForge settings do nothing in that start.
- **When Kiln cannot read the mod's settings file and your own ShroudForge runs it,** the row points you to ShroudForge's own Modloader window.
- **Chinese, Japanese and Korean text in mods no longer shows as `????`.** Mineral Production Boxes names its resources and settings in Chinese, with the English item name after it ("矿石 | 铜矿 / Copper Ore"). Kiln's menu only had Latin letters, so in an English game those labels, group titles and hints were all `?`. Now, when Kiln is asked to draw such text, it loads the game's own Chinese font (the one the game uses in Chinese; it also covers Japanese kana and Korean). The text can show `?` for a moment the first time, until the font is loaded. Nothing is downloaded. The font uses about 19 MB of memory from then until you quit, which is the same as playing with Kiln or the game set to Chinese.
- **Thanks to HTR** for the report, the details and the screenshot.

## Modders

- No mod API change.
- **The Kiln menu's ShroudForge group** (`ModCatalog`, `SfiCatalog`):
  - An EML row disappears when a profile ShroudForge entry has the same folder. That is the launcher's `emlRuntime` compatibility entry; the ShroudForge row then stands for the mod.
  - An EML row also becomes a ShroudForge row when two things hold. First, its package is ShroudForge's by its `extended.mod.json` (`ModCatalog.IsSfOwned`): either it has no `"launcher": "EML"`, or it says EML but has a non-empty `settings`, `groups`, `links` or `changelog`. Second, that package's folder is in ShroudForge's mods folder while ShroudForge runs (or was to run) that folder. The row then shows ShroudForge's runtime state.
  - In a kiln-backend start, such a row moves too: before the interpreter reports, where its record names the package, and while ShroudForge's own loader runs the folder.
  - ShroudForge's bare stamp (`$schema`, `schemaVersion`, `enabled`, `targets`, `"launcher": "EML"`, empty `settings`) and Kiln's own switch in its EML copies are not ShroudForge's, so real EML mods never move.
  - The Library still imports such a package as kind `eml`, and kiln-eml and the interpreter's plan treat it as before. Only the menu's grouping changed.
- **If your ShroudForge mod is meant to run only under ShroudForge,** leave `"launcher"` out of your `extended.mod.json`, or set it to `"SF"`. Kiln's launcher then imports it as a ShroudForge mod. `"launcher": "EML"` tells ShroudForge and Kiln that the package is an EML mod.
- **CJK in kiln.ui:** kiln-ui.dll checks the text it is given to draw: labels, texts, combo items and text field values, through any `Ui` call and the render service. At the first Chinese, Japanese or Korean character, it merges the game's zh-CN font group into the overlay's fonts for the rest of the process. Kiln's language and the game's language still pick their own group first (`native/services/ui/text_glyphs.h`, `font_group.h` `wanted`; docs/kiln/translating-game.md). kiln.log: `ui: a text in Chinese, Japanese or Korean is drawn (a mod's) ...`.

## Not yet seen in a real game

- None of this has been tried with Mineral Production Boxes in a game. HTR's kiln.log has not arrived, so the exact start (Kiln hosting ShroudForge, his own ShroudForge install, or Kiln's interpreter) and the mod's folder (Kiln's copy, or one ShroudForge's installer placed) are inferred from his report and screenshot. The tests cover all of these over fake state files and folders.
- The Chinese font joining in a real English game: host tests load it from a fake game resource with a system font, and the same loading path already runs for players who play in Chinese.
- F9 not opening ShroudForge's own Modloader window after a save loads, with your own ShroudForge install: unchanged. In that setup Kiln does not take F9 for ShroudForge, and ShroudForge's window reads the key in its own program, so Kiln's own key bindings (Kiln Auto Loot's F9 among them) cannot keep the key from it. A kiln.log of such a start will show more.

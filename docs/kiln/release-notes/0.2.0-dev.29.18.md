# Kiln 0.2.0-dev.29.18

## Players

- **Kiln and OptiScaler.** Kiln now recognises [OptiScaler](https://github.com/optiscaler/OptiScaler) (the upscaler and frame generation tool) in the game folder under any of its names. With OptiScaler's own in-game menu on (its default), Kiln's overlay steps aside on its own, as it does for NVIDIA Streamline: Kiln's key bindings, the Mods entry and mods' menu rows keep working, and the Mods entry says "OptiScaler is installed". Before, both overlays hooked the same graphics calls and both menus opened with Insert, and Kiln's menu could stay missing. To have Kiln's overlay with OptiScaler, set `OverlayMenu=false` under `[Menu]` in `OptiScaler.ini` (OptiScaler's own menu and frame generation go off; its upscaling keeps working): Kiln then draws as it does without OptiScaler. `KILN_UI_OVERLAY=1` still tries both at once. The launcher's Play page names OptiScaler and says what to expect, the support report includes `OptiScaler.ini`, and an OptiScaler package added to the Library is left out as a tool that runs on its own. Not yet checked on a PC with OptiScaler. Details: [ui.md](../ui.md#optiscaler).
- **One ShroudForge startup mod that fails no longer costs you the others.** ShroudForge writes its startup mods (the ones that change game data) into the game files in one pass before the game starts. When one of them failed there, for example because another mod had changed the same data, ShroudForge put the game data back and the game started with none of them. The ShroudForge that comes with Kiln now runs that pass once more without the mod that failed (and without mods that need it), so the others load. kiln.log names the mod and its error, and the launcher (Mods > Engines, the Deck's Home) and the support report warn with its name and error and suggest turning it off or checking for a clash with another mod. It tries again only once, and not for failures that are not one mod's (access denied, the game's files). Details: [shroudforge.md](../shroudforge.md).
- **A Kiln mod unzipped into EML's `mods` folder now says so.** Kiln's EML support listed such files as "? skipped: no mod.json (not an EML mod)". It now says it is a Kiln mod and to add its zip in the launcher (Library, Add mods; on a server, unzip it into `kiln/mods/<mod>/`), and logs that as a warning. This covers a Kiln mod's folder or zip there, and one unzipped loose. Other zips without a `mod.json` now say so instead of "specified file not found in archive".

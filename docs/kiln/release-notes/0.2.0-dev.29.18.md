# Kiln 0.2.0-dev.29.18

## Players

- **Kiln's own graphics tools: a frame cap, DLSS settings and a readout.** The Kiln menu (Insert) has a new **Graphics** tab, and the launcher's Settings page a **Graphics** card, for what players used extra mods for: a frame cap that paces the frames the game renders (20 to 500 a second; the finished frame is shown at once and the game starts its next one on time), the DLSS render preset (J, K, L or M, the ones the game's DLSS has) and the DLSS render size (DLSS's own, one scale for each DLSS mode, or one scale for every mode; DLAA stays as the game has it), and a readout in the top right corner with the frames rendered and shown a second, the frame time, the upscaler, its mode, render and output size and the DLSS preset. Everything is off until you turn it on, and nothing changes for anyone who does not. The cap and the readout apply at once, DLSS settings when the game next sets DLSS up (a world load, or a DLSS or resolution change in the game's settings); a DLSS setting turned on for the first time applies from the next game start. Kiln's frame cap and DLSS settings step aside on their own when OptiScaler, a DLSS frame generation mod (Streamline, `EnshroudedVKFG.ini`), DLSSTweaks or another DLSS loader is installed, and the Graphics page says why. Not yet checked in a real game. Details: [graphics.md](../graphics.md).
- **Linux: the launcher says when its window cannot start, instead of leaving it empty.** When the launcher's page has not come up 15 seconds after the window opened and the launcher has nothing left to try by itself (it already draws without the GPU, or you asked for a mode), a message now says what it tried, where launcher.log is, and what you can still try: "Start without the GPU" (when it drew with it), "Start without WebKit's sandbox" (when WebKit runs it), "Open the log folder", "Quit". The cause of an empty window is often not known, so each button is a try. The message is the system's own (GTK; zenity, kdialog or a desktop notice when GTK cannot show it), not part of the launcher's page. Details: [app.md](../launcher/app.md#webkits-sandbox-linux).
- **Linux: WebKit's sandbox, your choice.** The launcher checks at each start whether the sandbox WebKit would use (bubblewrap, `bwrap`) can start on your system. In a normal start WebKit does not use it for the launcher (WebKitGTK's GTK 3 version uses it only when `WEBKIT_FORCE_SANDBOX=1` is set), so this changes nothing for most players and does not explain an empty window on Ubuntu 24.04 and systems built on it. When WebKit would use it and it cannot start (where WebKit would end the launcher at once), a message before the window offers "Turn the sandbox off and start" (where the launcher can), "Start anyway" or "Quit", and names the proper fix. The launcher never turns the sandbox off by itself. Settings > Appearance > "WebKit's sandbox" turns it off or back on for the next start; `--no-webkit-sandbox` / `--webkit-sandbox` and `KILN_LAUNCHER_WEBKIT_SANDBOX=off|on` do it for one start. launcher.log has `sandbox:` lines and the support report a `WebKit sandbox:` line.
- **Linux: "Draw the launcher without the GPU" works at the start again.** Since 0.2.0-dev.29 the launcher did not read that setting when it started (a change for test builds held its data folder until after the window was made), so a launcher that had fallen back to drawing without the GPU started with the GPU again each time, and its first log lines (how it draws, the WebKitGTK version) only went to the terminal. Both work again. If the setting is on for you (you turned it on, or the launcher did after a start whose window stayed black), the launcher now draws without the GPU at every start, also where it drew with the GPU in the versions before; turn it off in Settings > Appearance to draw with the GPU again. The switch's text and launcher.log say when this is why.
- **Kiln and OptiScaler.** Kiln now recognises [OptiScaler](https://github.com/optiscaler/OptiScaler) (the upscaler and frame generation tool) in the game folder under any of its names. With OptiScaler's own in-game menu on (its default), Kiln's overlay steps aside on its own, as it does for NVIDIA Streamline: Kiln's key bindings, the Mods entry and mods' menu rows keep working, and the Mods entry says "OptiScaler is installed". Before, both overlays hooked the same graphics calls and both menus opened with Insert, and Kiln's menu could stay missing. To have Kiln's overlay with OptiScaler, set `OverlayMenu=false` under `[Menu]` in `OptiScaler.ini` (OptiScaler's own menu and frame generation go off; its upscaling keeps working): Kiln then draws as it does without OptiScaler. `KILN_UI_OVERLAY=1` still tries both at once. The launcher's Play page names OptiScaler and says what to expect, the support report includes `OptiScaler.ini`, and an OptiScaler package added to the Library is left out as a tool that runs on its own. Not yet checked on a PC with OptiScaler. Details: [ui.md](../ui.md#optiscaler).
- **One ShroudForge startup mod that fails no longer costs you the others.** ShroudForge writes its startup mods (the ones that change game data) into the game files in one pass before the game starts. When one of them failed there, for example because another mod had changed the same data, ShroudForge put the game data back and the game started with none of them. The ShroudForge that comes with Kiln now runs that pass once more without the mod that failed (and without mods that need it), so the others load. kiln.log names the mod and its error, and the launcher (Mods > Engines, the Deck's Home) and the support report warn with its name and error and suggest turning it off or checking for a clash with another mod. It tries again only once, and not for failures that are not one mod's (access denied, the game's files). Details: [shroudforge.md](../shroudforge.md).
- **A Kiln mod unzipped into EML's `mods` folder now says so.** Kiln's EML support listed such files as "? skipped: no mod.json (not an EML mod)". It now says it is a Kiln mod and to add its zip in the launcher (Library, Add mods; on a server, unzip it into `kiln/mods/<mod>/`), and logs that as a warning. This covers a Kiln mod's folder or zip there, and one unzipped loose. Other zips without a `mod.json` now say so instead of "specified file not found in archive".
- **No more "One Steam setting" banner where it is not needed, by bisdat.** On Linux with GE-Proton 11-11 or newer chosen for Enshrouded in Steam (for the game itself, or as Steam's default for all games), Proton loads Kiln by itself, but the launcher's Play page and the Deck's Help still asked for the `WINEDLLOVERRIDES="dinput8=n,b" %command%` launch option. The launcher now reads which Proton Steam uses for the game and leaves the advice out there. Older and unknown Proton builds keep it, and if a game start really runs without Kiln ("No Kiln"), the launch option is offered again as the fix, whatever the Proton. The separate advice for Ultimate ASI Loader (`xinput9_1_0`) is unchanged. (GitHub #77, pull request #78.)
- **A ShroudForge mod you switched off no longer runs through XHL-Core.** Some ShroudForge mods are XHL-Core plugins too, such as Building Tools for ShroudForge. When a profile had one off, or did not have it at all, Kiln switched it off for ShroudForge but its folder stayed in the game's `mods` folder, and XHL-Core still loaded its DLL from there. Without its ShroudForge side, the game could crash at every start. While such a mod is off, Kiln now renames its `native-plugin.ini` to `native-plugin.ini.kiln-off`, so XHL-Core skips the folder, and renames it back when you switch the mod on. Settings the mod keeps in that file stay as they are, also through an update of the mod. Kiln does this only in the copies it placed itself, never in a folder you put there yourself, and also when the mod's version is no longer in the Library. The old notice that such a mod "may still run from there" is gone. Where the game has XHL-Core, a note says once what Kiln renamed.
- **The support report has XHL-Core's own log.** When XHL-Core is installed, the report now includes its `XHL-Native-Plugin-Host.log`, from the game folder or from Kiln's copy of XHL-Core, with your paths and names taken out as in Kiln's own logs. It shows which XHL plugins XHL-Core loaded, skipped or refused.

- **A better upscaler behind the game's FSR 3 option.** Choose FSR 3 in the game's settings as usual, and Kiln can run AMD FSR behind it: FSR 4 on graphics cards and drivers that run it (recent AMD cards), else FSR 3.1, with Kiln's setting to keep FSR 3.1. It uses the game's own image, depth, motion and masks, records into the game's own frame, and stays off until you choose it (`graphics.upscaler` in `kiln.json`). Kiln adds what it needs to the game's graphics device at the game's start, so a choice made while the game runs needs a restart the first time. AMD's files come from the launcher's Upscalers section; Kiln checks every file against the copy it pins before the game uses it, and only from Kiln's own folder. When a file is missing, the card lacks something, or anything fails, the game's own FSR 3 runs and Kiln says why. Kiln steps aside for OptiScaler and other upscaler tools. Not yet checked in a real game; FSR 4 needs a tester with an AMD card. Details: [graphics.md](../graphics.md#upscaler-behind-the-games-fsr-3-020-dev2918).

## Modders

- **`graphics_status` in kiln_ui.h** (native plugins): what Kiln's frame cap, DLSS settings and readout do now (the cap, frames rendered and shown a second, the DLSS in use with its mode, preset, render and output size, and what the tools step aside for). Appended after `set_texts` with `graphics_set` (Kiln.Ui's only: a native plugin's call is refused). No managed member in this release. Details: [graphics.md](../graphics.md#for-native-plugins-kiln_uih), [services/ui.md](../services/ui.md#kilns-graphics-tools-020-dev2918).
- **The upscaler's status in `graphics_status`.** The struct grows from 72 to 248 bytes: which upscaler runs behind the game's FSR 3 option, a stable reason code when the chosen one does not, flags, what it steps aside for, its version, the pass's sizes and a short English detail. A 72-byte caller still gets the fields it knows. Details: [graphics.md](../graphics.md#for-native-plugins-kiln_uih).

# Kiln 0.2.0-dev.29

OnBoot now runs in a player's game, not only on a dedicated server. In 0.2.0-dev.28 a mod with `"boot"` (for example More Flame Altars) loaded on a dedicated server but not in a game that hosts a world or joins a server, unless `"preview"` was set in `kiln.json`. That was a mistake in the release: the capability had been tested in a real game and should have shipped on.

## Players

- **Boot mods load in your game.** A mod that changes the game's data before the game reads it (More Flame Altars and others built on OnBoot) now works in a world you host and when you join a server, with no setting. If you added `"preview": ["mods.boot.client", "mods.boot.resource_patches"]` to `kiln/kiln.json` for dev.28, it is no longer needed; leaving it does no harm.
- A dedicated server that runs a boot mod its players need no longer turns away players who have Kiln and the mod: their game now loads it.

## Mod authors

- `mods.boot.client` and `mods.boot.resource_patches` are open on a game client: `Mod.OnBoot`, boot definitions and resource patches run there as on a dedicated server. Confirmed in a real game on 0.2.0-dev.28 with More Flame Altars (a hosted world: `OnBoot` ran, the boot generation was published, and 42 values of `altarsPerFlameLevel` were patched before the game read them).
- `mods.boot.vfx` stays held on a game client until its game test: a boot mod's VFX and materials are built after the start there, as for any other mod.

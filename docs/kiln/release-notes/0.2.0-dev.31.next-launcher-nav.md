# Kiln 0.2.0-dev.31.next: leaving a server's page, and the report's EML line

## Players and server admins

- **Play now leaves a server's World and Players tabs.** On a server's page, clicking Play in the launcher's main menu while on the World tab opened the server's Players tab instead, and on the Players tab it did nothing. Every main menu entry now goes to its own page from every server tab. Thanks to netjunk for the report.
- **Unsaved changes on a server's page now ask before you leave.** If you leave a server's Settings with unsaved changes, or a stopped server's config file you edited by hand, the launcher asks first: Save and leave, Discard changes, or Stay. This covers every way out: the main menu, the server's tabs and switcher, and Back. If the change cannot be saved right now, only Discard and Stay are offered. With nothing unsaved, nothing asks. The same check covers a mod's config file edited by hand elsewhere in the launcher. Suggested by netjunk.
- **The support report now says when kiln-eml handed its EML packs to ShroudForge.** When Kiln hosted ShroudForge, kiln-eml hands it the EML packs, which ShroudForge then runs. If a report was written before ShroudForge's own state file existed, it said "kiln-eml stood aside at the last start: EML's own loader runs in the game" as a problem, though no EML loader ran. It now reads, for example, "kiln-eml handed your 8 EML packs to Kiln's ShroudForge at the last start", as information. It mentions EML's own loader only when that loader is really there.
- **The support report no longer says Kiln did not load when the game ended while Kiln was starting.** A start that ended during Kiln's own start (in a player's report, a second in, while ShroudForge prepared its mods) read "did not load Kiln: boot.json is missing", with advice about dinput8.dll and antivirus programs. Kiln had loaded. The report now says so, and at which step the start ended.

## Modders

- Launcher: the router is now a data router (`createHashRouter`, with one splat route around `App`'s routes), so that the unsaved-changes guard can block navigation (`useBlocker`). Pages register unsaved work with `useLeaveGuard(dirty, { what, save?, discard })` (`launcher/src/shell/leaveGuard.tsx`). The page that is still shown while the sheet drops now keeps the address it was opened at.
- Report: kiln-eml's `aside` reason from Kiln's ShroudForge plugin speaks for the start that its `eml.json` pid names. The last start is kiln.log's last boot, else boot.json's; the file speaks for it when its pid is that start's, or ShroudForge's `hosted` pid of that same start. A file from another start gets an Info finding saying so (`eml-under-shroudforge`). It no longer gets the generic `own-loader` problem.
- Report: after a start from the launcher with no fresh boot.json, a `kiln/state/progress.json` of that start that is not `ready`, `idle` or `failed` makes the `not-loaded` finding say that Kiln loaded (its pid) and the step the start ended in, instead of "did not load Kiln" and the dinput8.dll advice.

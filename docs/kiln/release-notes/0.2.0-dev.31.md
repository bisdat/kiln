# Kiln 0.2.0-dev.31

Kiln adds a shared registry stage for mods and data packs, richer in-game UI, and tools for building multiplayer mods and NPCs. Mod API: **0.2.17**.

## For players and server admins

- **Registry conflicts.** See which mods edited the same game data, which edit won, and why an edit was refused in the launcher's Conflicts view.
- **Richer mod UI.** Mods can give characters their own saved values, open richer windows, add map markers and labels, customize crafting-station menus, tint inventory slots, and add a game-drawn action to a storage chest.
- **Survivor recruiting.** Mods can recruit and house survivors, assign daily routines, set base rules, and give friendly NPCs custom bodies and animations. Custom bodies are enabled. With `modSync: off`, players without a matching body can join but may crash when the game loads that NPC.
- **Camera control.** Mods can play camera paths and follow views, including server-driven views for compatible Kiln clients.
- **Clearer player-storage and crafting diagnostics.** If a modded bag can't be set up, Kiln logs the failed creation or cleanup stage. It retries once only on a gate refusal before native creation starts. Player crafts also log how far linked-stock payment got, subject to rate limits; this does not change payment behavior or resolve the reported crafting issue.
- **Item icons.** Scrolling item icon buttons out of view no longer changes their layout. The item-icon cache has configurable entry and memory limits.
- **SF Survival's Infinite Frost Timer.** Kiln no longer refuses its body-heat write. On both ShroudForge backends (the hosted ShroudForge runtime and Kiln's own interpreter), body heat is now calculated the way the game does, as a signed value, and stays within the same safe range. Other attribute writes with mismatched number types are still refused. Thanks ewabs.

## For mod authors

- **Stable registry IDs.** Edit items, recipes, loot, drops and balance through Kiln-supplied names. Kiln translates proven fields for the running game build, and reports unproven changes rather than guessing. Mods choose `GameStart`, `ModLoad`, `WorldLoad` or `HotReload`, or open an explicit transaction.
- **Add items and recipes, hide recipes and loot.** Experimental `AddLike` and `Remove` are GameStart operations. Stable IDs survive restarts, and absent mods leave placeholders for their saved item IDs. Hiding preserves game records. Whole item removal is refused on the current game build because it requires drop fields that are still unproven.
- **Mod data and network inspection.** Send small per-entity payloads to Kiln clients, watch entities, and see per-peer traffic. Mods can provide vanilla stand-ins for Kiln-only items.
- **Cloth and chains on models.** Model authors can add game-simulated cloth and bone chains.
- **Debugger in the game client.** Mod authors can attach a debugger in the game client or on a Windows dedicated server.
- **Inventory owners, over-menu draws, and slider steps.** Use the typed inventory-owner query, or list the containers in a base without changing the crafting-stock API. The base query includes Magic storage and plain containers, which can include refilling trees; it does not grant chest permissions. Use `WorldOverMenus` to opt in to drawing world primitives on game menus. Optional `[Range(min,max,step)]` steps affect slider interactions, not saved values or command validation. Same-owner `Items.Move` remains refused; use `Items.Unequip` to take off worn equipment.
- **Require a specific dev build.** A requirement like `kiln >= 0.2.0-dev.30.9` now rejects earlier dev builds. A plain requirement such as `>=0.2.0` still accepts dev builds of the same core version.

## Verification and limits

Dedicated-server and offline checks cover registry edits, missing-mod placeholder replay, NPC admission, and camera routing. Real-client rendering and animation, hosted-world gameplay, SF Survival's Infinite Frost Timer in a real game, and direct-drop behavior on a build with proven mappings are not verified. Base rules do not lift the game’s build-area save limit past roughly 240 m.

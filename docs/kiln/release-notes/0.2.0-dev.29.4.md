# Kiln 0.2.0-dev.29.4

A patch for 0.2.0-dev.29.3: plugin-loader and Ultimate ASI Loader mods run from the game folder, Item Skill Descriptions works beside Auto Doors, and Kiln names the Shroudlink core file that stops your Shroudlink mods. The SDK stays at 0.2.0-dev.29. Everything else is as in 0.2.0-dev.29.3.

## Fixed

- **Item Skill Descriptions works beside Auto Doors.** Item Skill Descriptions 0.3.0 checks the game function it changes before it changes it, and Auto Doors 1.1.0, which starts earlier, had already hooked the same function, so Item Skill Descriptions stayed inactive. When both are on, Kiln now starts Auto Doors after Kiln's Shroudtopia host has started its mods (at most 30 seconds after the host starts; `kiln.log` says what waited and for how long). Auto Doors works on top of the other hook. With Item Skill Descriptions off, Auto Doors starts as before. Together with 0.2.0-dev.29.3's fix for Shroudlink's K tab, all three run side by side.
- **Mods that only work from the game folder now get there.** A plugin loader such as "Autoloot and coop loot sharing" (`powrprof.dll` with its `plugins` folder) did nothing under Kiln, because Kiln loaded it from its Library folder, where it found no plugins. When such a mod is switched on, Kiln now copies its files into the game folder, and the game loads it itself. When you switch it off or remove it, Kiln takes out the files it put there. Settings you changed stay, and so does a `powrprof.dll` Kiln did not put there (Shrouded Engine Tweaks' loader, or your own copy): then Kiln says that it left the mod out. You don't need to add the mod again. Under Proton the game needs a DLL override for that file, and the launcher's notes name it.
- **Ultimate ASI Loader and `.asi` mods work next to Kiln.** Add Ultimate ASI Loader's download (its `dinput8.dll`) and an `.asi` mod such as Smart Workshop (its `Scripts` folder) to the Library like any other mod. Kiln puts Ultimate ASI Loader next to the game as `xinput9_1_0.dll`, so Kiln's own `dinput8.dll` stays, and the plugins go where the loader looks for them. Kiln takes them out again when you switch them off. An `.asi` mod alone uses the Ultimate ASI Loader Kiln's installer already set up, if there is one. Don't copy Ultimate ASI Loader's `dinput8.dll` into the game folder yourself: that would replace Kiln. On Linux (Proton) the launcher asks for `xinput9_1_0` in the Steam launch option.
- **Shroudlink singleplayer: Kiln names the file that stops your Shroudlink mods.** If a `shroudlink_core.dll` from an earlier hand installation is still in the game folder, Shroudlink's client addon starts that core, and your profile's Shroudlink mods (Expeditions, Assistants) don't load ("no mods on this server"). The launcher, `kiln.log` and support reports now say to remove `shroudlink_core.dll` from the game folder, and Kiln then runs the mods. Keep the client addon on: it draws the MODS tab. The hint names the core file Kiln actually found, also when it was started from `kiln/chain`. Before, the hint named the wrong files.
- **Kiln's handling of game-folder files is careful with your own files.** Kiln writes a file into the game folder only where there is none or where its own copy still is, never replaces a file it did not put there, and removes only its own unchanged files. A change that is interrupted (the launcher crashes or is closed) is settled at the next activation. Vanilla and No mods refuse to start while a loader Kiln placed is still in the game folder: switch the mod off and activate first. On a drive without hard links (some SD cards and network drives) Kiln refuses to place these packages and says why.

## Mod authors

- 0.2.0-dev.29.4 ships the launcher and the runtime only; keep using the 0.2.0-dev.29 SDK (mod API 0.2.4).
- `native/core/compat-rules.json` has a new action, `defer`: it keeps a named native mod back until the Shroudtopia host's first pass when a named Shroudtopia mod is on (bounded by `max_wait_ms`). A native mod with an `init` is never deferred.

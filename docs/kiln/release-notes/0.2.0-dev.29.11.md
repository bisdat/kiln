# Kiln 0.2.0-dev.29.11

The gem system for mods and Kiln on the main menu, with a new SDK (mod API 0.2.5): mods can read gems, make new ones, run the Shroud Forge's actions from code and give rings, armour and shields a gem socket. Everything else is as in 0.2.0-dev.29.10.

## Players

- **Kiln on the main menu.** Above the game's build number the main menu now shows Kiln's mark and "Kiln 0.2.0-dev.29.11 - N Mods Loaded" (every mod that started, of any kind), drawn in the game's own footer style. It takes the place of XHL-Core's line, including XHL-Core's own warnings there ("Game updated", "Mod conflict"); Kiln setting **mainMenuFooter** (Mods page, Kiln settings) turns Kiln's line off and brings XHL-Core's back.
- **Nothing changes until a mod asks.** Without a gem mod, gems, the forge and its lists work as before.
- **The Shroud Forge lists rings and armour that have a socket** on a Kiln client, when a mod on the server gives such gear sockets. Take the piece off first: the forge lists what is in your backpack and on your action bars, not what you wear. A player without Kiln on the same server sees the game's own lists.
- **A mod's gem no longer turns into its base gem when the mod is removed.** After a restart without the mod it stays in your inventory or socket as a placeholder named `[Missing: …]`. A gem whose effect was the mod's own code does nothing; a copy of a game gem keeps that gem's effect with the game's numbers. A mod that gives non-weapon gear sockets can hand every socketed gem back before a server stops using it (`Gems.ReturnSocketedGems`).

## Mod authors

- **The mod API is 0.2.5.** Everything new is additive: no public member of 0.2.0-dev.29 was removed or changed. Use the 0.2.0-dev.29.11 SDK and MDK. Start with the Gems guide, `docs/kiln/services/gems.md`.
- **Read gems.** `Gems.Catalog`, `Gems.Get`, `Gems.Equipped(player)` (every gem the player's worn gear carries, with its level and impact slot) and `Gems.Socket(item)` (what an item's socket holds). Capability `gems.read`.
- **Gem events.** `GemTriggeredEvent` when a socketed gem does something (damage, a buff, a spawn: the player, gem, carrier, level and target) and `GemSocketChangedEvent` when a socket is filled, emptied or upgraded or its gem is destroyed, however it happened. A gem whose effect is your C# handler calls the handler instead of posting `GemTriggeredEvent`.
- **New gems: `Gems.Register`.** A copy of a game gem with its own GUID, name, texts, icon, rarity and level range. Its effect is the base gem's program (optionally with other numbers), any other loaded Impact program with your numbers, or C# code: `GemTrigger.OnHit` (optionally crits only), `OnKill`, `OnBackstab`, `OnHitTaken` and `Passive(interval)` call your handler with a `GemTriggerContext` (player, target, gem, level, carrier, damage, position and more). Removed with your mod; the items stay until the server restarts, then saved gems become kiln.content placeholders: a trigger gem does nothing (it no longer runs its base gem's program), a gem on a game program keeps it with the base's numbers. Capability `gems.triggers`. Data packs can clone a gem through kiln.content with its own `impactValues`. Guide: `docs/kiln/services/gems-new.md`.
- **Forge actions from code.** `Gems.Socket`, `Gems.Unsocket`, `Gems.Upgrade` and `Gems.Recycle` run the forge's own transaction with its rules and costs and answer a `GemCraftResult` (Done, or why not: NotEnough, NoForge, NoRoom, MaxLevel, Occupied and more, with what was paid and received). `GemCraftOptions.Cost` makes an action free or gives it another price. `GemCraftingEvent` comes before a player's forge action and can refuse it (nothing is paid or moved); `GemCraftedEvent` comes after every action with the price and the gem's level before and after. Every action needs a forge. Capability `gems.craft`. Guide: `docs/kiln/services/gems-forge.md`.
- **Sockets on other gear.** `Gems.AllowSockets(kinds, rollChance)` lets new rings, armour, shields or other gear roll a socket (weapons keep the game's roll); `Gear.GemSlot` reads and writes a socket on allowed gear; `Gems.AddSocket(item)` gives an existing piece a socket and keeps its level, upgrades, rarity, dye and durability (the item gets a new entity; worn items are refused). It checks the new item one step later and answers `Incomplete` with what is missing (`GemSocketResult.Missing`) if any of that did not carry over. A socketed gem works from any worn piece. `Gems.ReturnSocketedGems(owner)` gives back every gem in an owner's non-weapon gear, free. Data packs may set `"gemSlotOverride": true` on any gear. Capability `gems.sockets`. Guide: `docs/kiln/services/gems-sockets.md`.
- **The Gem Forge's GEMS list.** `Ui.Values.GemForgeCandidates()` and `SubscribeGemForgeCandidates` give a read-only copy of the list the forge shows on a game client: loose gems and gems already in a weapon, with the selected row. Capability `ui.gemforge.inspect`. Guide: `docs/kiln/ui-gemforge.md`. (GitHub #42)
- **Samples:** `mods/samples/GemSample` (Gem of Deep Cuts, a Bleeding copy with its own icon and texts; an opt-in tweak of the game's Gem of Bleeding) and `mods/samples/GemEffects` (Gem of Frostbite: a crit slows; Gem of Renewal: a kill heals).
- **C:** kiln.items v7 (`KILN_ITEMS_GEM_SLOT_ANY`, `KILN_ITEMS_REPLACE`, `KILN_ITEMS_DYE`, `KILN_ITEMS_DURABILITY`, `socket_roll`), the new service kiln.gemcraft (`kiln_gemcraft.h`), kiln.ui.values `gemforge_sockets` and the Gem Forge list members.

## Fixed

- **A mod switched off in your profile no longer locks you out.** Kiln still listed it as a mod players need, so a game hosting its own world refused its own player ("This server requires mods you do not have"), and a dedicated server refused players without a mod it had switched off. Mods switched off in the profile are no longer listed; a mod a server skips because it is only for clients still is.
- **Greeneye mods start when a thread of the game can't be opened.** On some PCs (security software is the usual source of such threads) Kiln refused to write any Greeneye mod's hooks, so mods like The Worst Map Mod and Continue never started, and the Greeneye start took about a minute of retries. Kiln now does as Greeneye Loader itself: such threads don't hold the hooks back, and kiln.log names them. When a hook write does wait, kiln.log now says which thread and why, and a mod that could not start says so instead of "generation 0 stays active".
- **An item's program served through kiln.assets is accepted.** kiln.content refused an item whose `program` named an Impact program a mod serves through kiln.assets, without saying why; it now resolves it like a game program.

## Checked in a real game, and what is not yet

Checked on a game client that hosts its own world (Linux, Proton): the new gems' names, icons and levels; socketing and upgrading at the Shroud Forge by hand with the four events; Frostbite's slow on a crit and Renewal's heal on a kill; a refused Recycle (nothing paid, nothing moved); rings with a socket listed and socketed at the forge, and the forge's normal lists again once no mod asks for sockets; `Gems.Equipped` with a worn ring; a code action refreshing the open forge screen; `Gems.AddSocket` and `Gems.ReturnSocketedGems` (after fixes this test found); sockets kept after leaving and joining again; a removed mod's gems doing nothing.

Not yet seen in a real game: a dedicated server with a separate Kiln client (the forge lists widen on that client), a player without Kiln on such a server, the German texts, and tooltips after a data-pack change.

# Kiln 0.2.0-dev.31.next (ammo-keep part; work-cm renames and merges this file)

## Players

- **Spellbook lists stay put while you scroll.** A mod that puts its own spells or arrows in place of the game's HUD list (Grimoire, for example) no longer flashes the game's own list for a moment after each switch, and on a dedicated server the cursor no longer jumps back to the equipped spell while you scroll on, so you no longer need to stop on each spell (#151). Thanks Fuzen777.

## Modders

- **`Ui.AmmoList` in `Replace` keeps its rows over the game's new build (#151).** When the game builds the list again (a swap changed the backpack), the rows shown last and the cursor on them stay up until Kiln.Ui publishes the providers' rows for the new build, instead of the game's own rows and the game's selection. Picks of them are decided against the game's new rows (the backpack check of #145). The keep lasts at most 1 s, then the game's rows show until the next publication and kiln.log says so once; nothing is kept over another weapon, player, client session or world, or after the list is cleared. `Append` is unchanged. No API change (default behaviour of `Replace`; mod API unchanged), so Grimoire's 250 ms rest before a pick is no longer needed for this. Thanks Fuzen777.

## Not yet seen in a real game

- Scrolling a `Replace` spell list through swaps in a hosted world and on a dedicated server (Grimoire); tested in kiln-tools' host tests over the selector fixture.

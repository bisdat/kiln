# Kiln 0.2.0-dev.31.17

## Players and server admins

- **Registry edits now take effect for more fields.** Mods that change loot rarities, fixed rarities, scaled loot stacks, drop tables, shield block, instrument comfort or stamina cost through Kiln's registries now change the game on this build (98 of the 100 registry fields are proven, up from 86).
- **Mods can remove items.** A removed item no longer drops as loot, shows in recipes or comes from drop tables. Items you already own stay.
- **Roll back registry changes.** `kilnctl registry rollback <server>` starts the next boot on the last registry plan a world started on cleanly, and says exactly what changes back. It never touches saves, and `--clear` goes back to the mods' current edits. The launcher's Conflicts view has the same as Roll back / Clear, with a dry run first. A rollback is refused whole when one of its mods is missing or changed, or when it would narrow an item's level range or shorten the build-zone list against the world it rolls back from.
- **Registry edits can no longer damage saves.** A lower max stack keeps existing bigger stacks whole. A narrower item level range or a shorter build-zone list is refused with a reason. Other edits that change what saved data means are listed under `saves` in `kiln/state/registry.json`. A damaged `plans/index.json` is kept aside and reported, and a hand-edited rollback request can no longer stop the game from starting.
- **Joining a server also checks the registry balance.** When you and the server run the same shared mods in the same versions, joining also checks that your game made the same registry balance changes (such as level cap or XP values). If they differ, a clear message says to use the server's modpack and settings and restart the game. A different load order with the same resulting values is not reported to you, and older Kiln versions join as before.
- **Item and recipe changes reach joined players.** Item and recipe changes a server makes while you're connected reach you without rejoining. Values the game reads at world load (such as stack limits) apply at your next world load.
- **Reloads say what waits for a restart.** `kiln/control reload <id>`, `kilnctl status` and the launcher say which registry edits wait for a restart. A data pack that throws during a reload is undone completely (its items, game-data copies and other services' sections), and other mods' changes and the stack guard stay in force. Reloading a mod whose new version adds boot content is refused, and the running version stays loaded.
- **Other loaders' writers are named.** The Conflicts page names the ShroudForge and EML packages that wrote an entry before Kiln (items, drops, balance) and says their operation is not known, and it flags values changed outside Kiln as "best effort", without ever refusing them. Kiln's own boot patches are never flagged.
- **The Conflicts view is translated** into all launcher languages.

## Modders

- Mod API 0.2.24. One public addition, experimental like the rest of Kiln.Registry (KILNX031): `RegistryFieldAttribute.JoinedClient` and `RegistryFieldSpec.JoinedClient` say when a joined Kiln client sees a server edit of the field (`now`, `worldLoad`, `rejoin`, `restart`, `serverOnly`, `localOnly`, `unknown`); each registry page has a "Joined client" column. `applies` is unchanged.
- New lint KL213 registry-clients suggests the `clients` value for a data-only registry pack: a loot or drops-only pack can say `clients: "none"` so vanilla players can still join; balance edits need `clients: "mod"` with side `both`.
- Wire and formats: the handshake property `kiln.registry.boot` (older peers compare nothing); registry plans format 2 with their edits, `plans/index.json` and the rollback request `rollback.json`; `kiln/state/registry.json` gains `rollback`, `saves`, `migrated`, `bootSync`, `base.journal` and `RestartRequired: ` refused rows (`counts.restartRequired`); the `reload <id>` control reply waits for the reload's registry work (at most 5 s) and carries `data.registry`.
- Registry edits written for an older schema version are renamed to the current names before they are matched (registry.json `migrated`); no schema has a breaking step yet. Migrations also rename `where` fields, element leaves and `{"set": id}` references.
- An edit that lowers `items.levels.max`, raises `items.levels.min` or shortens `balance.buildzoneSizesPerAltarLevel` is refused. A new entry's own first values are not refused as save changes.
- `items.block` and `items.comfort` apply `now` (items schema 0.1.1); `items.staminaCost` needs the client, like `manaCost`. `items.fuel.burnTime` stays refused (the game never reads it); `recipes.station` stays refused until a stations registry exists.
- A live change no longer reports `PendingResource` because of another change's unloaded drop table. A fixed loot rarity can no longer be read, for an instant, as the old rarity.
- Archive-writer rows in registry.json have no `op` and are never a field's `winner`. A malformed change journal, or one reached through a link, names nobody.
- Known limit: after a reload, the reloaded mod's data packs apply after every other mod's until the next start, so a field another mod's pack also sets goes to the reloaded mod until then.

## Not yet seen in a real game

- Real loot rolls with edited rarities, and owned copies of a removed item across a real save and load.
- A real client refused for a registry balance difference.
- The stack guard with real oversized stacks, and a rollback on a hosting client.
- Named ShroudForge rows from a real kiln-mode start.
- The launcher's Conflicts view in each language.

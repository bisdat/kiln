# Kiln 0.2.0-dev.29.6

A patch for 0.2.0-dev.29.5: Item Skill Descriptions and Auto Doors now work side by side. The SDK stays at 0.2.0-dev.29. Everything else is as in 0.2.0-dev.29.5.

## Fixed

- **Item Skill Descriptions works beside Auto Doors, and Auto Doors keeps working.** Item Skill Descriptions 0.3.0 checks the game function it changes before it hooks it; Auto Doors 1.1.0 has hooked that function first, so Item Skill Descriptions stayed inactive and item tooltips were vanilla. (0.2.0-dev.29.4 tried starting Auto Doors later instead, which broke Auto Doors; 0.2.0-dev.29.5 took that back.) Auto Doors now keeps starting first, and when Item Skill Descriptions checks the function, Kiln shows it the game's original code. It then hooks on top of Auto Doors, and both run: the tooltips show the skill text and the doors work. Shroudlink's K tab keeps working next to both. `kiln.log` says "item-skill-text sees the game's original code …" when this applies. Checked with Kiln's own tests on Wine (a mod that hooks on top of an earlier hook, both running); not yet in the real game with these three mods.

## Mod authors

- 0.2.0-dev.29.6 ships the launcher and the runtime only; keep using the 0.2.0-dev.29 SDK (mod API 0.2.4).
- `native/core/compat-rules.json` has a new action, `original-code`, for a Shroudtopia mod: Kiln points that mod's imported `memcmp` at a version that compares against the game exe's original bytes where the live bytes differ only by another mod's entry hook. Kiln ships one such rule, for `shroudtopia:item-skill-text`.

# Kiln 0.2.0-dev.29.15

Item icons and names for mod windows, mod panels at production stations, chest gems at the Shroud Forge (GitHub #61) and new kinds of boot patches, with a new SDK (mod API 0.2.7). Everything else is as in 0.2.0-dev.29.14.

**Not yet checked in a real game.** This patch passed Kiln's tests and lab checks on a dedicated server, but nobody has played with it yet: what a game client draws or does (icons, the forge's GEMS list, panels at stations) has only been checked against the game's code, not seen on screen. If something looks or works wrong, tell us on GitHub or Discord with `kiln/logs/kiln.log`.

## Players

- **Nothing changes until a mod asks.** Without a mod that uses the new parts, your game works exactly as with 0.2.0-dev.29.14.
- **Chest gems at the Shroud Forge.** On a server with a mod that offers them, the gems in your chests show up in the forge's own GEMS list after your own, and you can insert, upgrade and recycle them without moving them into your backpack first. The mod can also let a chest (or your base's Magic chests) pay the essence. This needs Kiln 0.2.0-dev.29.15 in your own game as well; without it the forge works as usual. The game's forge itself only ever takes essence from your backpack.
- **Mod panels at kilns, smelters and other production stations.** A mod's crafting panel can now show next to a production station's own screen, not only at a workbench, when the mod asks for it. Mods' existing panels don't appear there.
- **Mods can show the game's own item icons and names**, in your game's language.

## Fixed

- **Expeditions finds your survivors again when you host your own world.** Expeditions (EMF, up to 1.2.x) kept saying "No free survivors nearby" while you stood next to them, and Send said "too far away", above all on slower PCs and the Steam Deck. Its once-per-step work for the game's client side cleared a value its survivor search on the server side was still using. Kiln now runs that mod's per-step work for the server side only, where all of its work happens. Thanks to Spirimtin for testing a diagnostic build.

## Mod authors

- **The mod API is 0.2.7.** Everything new is additive: no public member of 0.2.0-dev.29.14 was removed or changed. Use the 0.2.0-dev.29.15 SDK and MDK.
- **Item icons and names** (Kiln.Ui, Kiln.Items): `Ui.ItemImage`, `UiDraw.ItemIcon` and `Ui.ItemIconsAvailable` draw the icon the game draws for an item (a new item shows its base item's icon until its own is served), in windows, screens and crafting panels; `Items.DisplayName` gives the name in the player's language, also on a joined client. Nothing is loaded until a mod asks; a server has no icons. Guide: `docs/kiln/ui.md`.
- **Factory screens:** `CraftingScreen.IsFactory` and `CraftingScreen.Station` (the station's entity, read each frame); a `Ui.Crafting.AddPanel` panel shows at a production station's screen only with `CraftingPanelOptions.AtFactories` (off by default, so existing panels stay off those screens). There `Workshop` may be 0 or another station's: use `Station`.
- **Overlay images:** the overlay holds up to 960 images (fonts, mods' PNGs and item icons together; at most 8 new uploads a frame), and an image is drawn only once it is uploaded.
- **Stations:** `StationInfo.DisplayName`, `StationRecipe.DisplayName`, `Stations.WorkshopName` and `Stations.RecipeName` (any side, the player's language), `Bases.StockWithStations(id)` (the Magic chests plus outputs still in the stations). A mod that only automates stations can list `Stations` in `KilnServices` instead of `Blocks`, so players without Kiln can still join its server.
- **Behaviour changes:** base reads (`Storage`, `WaterSources`, `Stock`, `Stations.InBase`, `FindRoomFor`) answer empty instead of throwing when a base was rebuilt between reads or is gone; `EntityData.Waiting` counts only the calling mod's attachments (`EntityData.Matched` is new).
- **Gems at the Shroud Forge (GitHub #61, Kiln.Abilities):** `GemCraftOptions.GemHolder` and `CarrierHolder` (the gem and its carrier in different places, checked on the server, one transaction), `PayFrom` (`GemPayer`: the player, a chest, the base's Magic chests, or the player then the base) and `ReturnTo` (where an unsocketed gem and Recycle's essence go). The game still sets the price and takes it in one transaction; not enough means `NotEnough` with nothing paid or moved. `Gems.OfferChestGems` and `GemForgeOpenedEvent` put a container's gems into the forge's own GEMS list on Kiln clients; each offer is for one player, slot and item, works once, and anything without a live offer is refused. A mod needs only a server half. Capabilities `gems.payers`, `gems.sources`, `ui.gemforge.sources`. Guide: `docs/kiln/gems-forge.md`.
- **Boot patches** (Kiln.Blocks resource patches): append to a list (`append`), add and remove a template's components in place (`addComponents`, `removeComponents`), and `names:<kind>` reads in OnBoot. A patch document applies whole or not at all. Guide: `docs/kiln/modding/resource-patches.md`.
- **C:** `kiln_gemcraft.h` (`KilnGemRequest` grows to 80 bytes; a 56-byte request still works), new kiln.ui and kiln.ui.values slots.

## Checked

Lab checks on a dedicated server: item names from the server's data and no icons there; chest gems through the game's own forge requests (forged slots, duplicates, stale and withdrawn offers refused with nothing moved; chests paying; Recycle's essence into a chest; a hand take racing a request); boot patches (the boot structure test mod). Host tests for the icon decoder, the forge's client rows and the boot patches. Every new hook site and game value resolves in the client and server files of the current game version.

Not yet seen in a real game: icons and names on screen, the forge's GEMS list with chest gems (the look, selecting, the buttons, a real client's round trip), panels at production stations, and anything on a joined client.

# Kiln 0.2.0-dev.31.next: ShroudForge 1.8 mods with grouped choices can be added

Kiln now takes every setting that ShroudForge's own schema takes, including ShroudForge 1.8's grouped choices. Mods
such as Gear Up are no longer refused as "invalid metadata".

## Players and server admins

- **Gear Up and other ShroudForge 1.8 mods can be added again.** Add mods said "Nothing to add: gear_up: not a
  ShroudForge package Kiln can run: setting priorityPick has invalid metadata". Since 1.8, ShroudForge lets a mod sort
  a setting's choices into groups (a choice's label is then `{ "label": ..., "group": ... }`). Kiln only took plain
  text labels, so it refused such a mod that ShroudForge itself runs. The launcher's Add and Kiln's in-game Mods page
  now take both forms. We could not open Gear Up's own files (Nexus lists none for its archive), so this is the likely
  cause, built from ShroudForge's schema and its own starter mod.
- **Grouped choices in the Mods page.** On Kiln's in-game Mods page (Mods > ShroudForge), a list whose choices have
  groups shows each group as a small heading over its checkboxes. A single choice shows its group in front of the label
  ("Hands: Equipped weapon"). ShroudForge's own Modloader shows the groups as tabs.
- **A refusal says what is wrong.** When a mod really breaks ShroudForge's rules, the message now names the setting,
  the field and what ShroudForge expects, for example "ShroudForge would refuse setting priorityPick: option "x"'s group
  must be text", instead of "invalid metadata".
- **Thanks** to Ezra for the report (Discord #general).

## Modders

- No mod API change: mod API 0.2.26, as before.
- **Kiln accepts what ShroudForge's schema accepts.** Kiln's setting check was compared with `$defs.setting` in
  ShroudForge's 1.7.9 schema and in the 1.8.0 and 1.8.1 snapshots. The only change since 1.7.9 is the option label:
  text, or `{ "label": text, "group": text }`. `applyAt` stays optional: without it a setting applies at a restart, or
  live when `restartRequired` is false, as in ShroudForge. List values, min/max/step, text lengths, `enabledWhen` and
  every control were already accepted as ShroudForge accepts them.
- **The refusal messages** are `ShroudForge would refuse setting <key>: <what>`, with one wording for each field: the
  value's kind, `applyAt`, `applyAt` against `restartRequired`, empty options, a list without options, an option key
  that does not match the value's type, an option label or group that is not text, and an `enabledWhen` without a
  setting or an `equals`. The launcher, the sfi editor and the in-game page say the same.
- **Launcher form.** `settings_schema` puts each choice's label text in `x-kiln-enum-labels` (it held the label object
  for a grouped choice). The groups go in the new `x-kiln-enum-groups`, null for an ungrouped choice, and only when some
  choice has a group. kiln-manage adds `shroudforge::option_label` and `option_group`.
- **What the in-game page does not use.** The page reads past `presets`, `inputReservations`, tab groups (`tab: true`),
  `assetPreparation` and setting fields outside ShroudForge's schema, and leaves them as they are in
  `extended.mod.json`. kiln.log says so once per package: `ShroudForge mod <id>: Kiln's Mods page does not use presets,
  inputReservations, ...`. Picking a preset on Kiln's page does not change the settings it controls; ShroudForge's
  own Modloader does that.
- **sfi package model, 1.8 dialect.** It reads the `community-discord` and `video-youtube` links that ShroudForge
  1.8.1 added to its link list. ShroudForge's starter mod has both. The 1.7.9 dialect still refuses them.
- The shared fixtures (`schema/fixtures/shroudforge/cases.json`, now 84 cases, run by the launcher, the sfi editor and
  the in-game page) include a setting shaped like Gear Up's priorityPick and ShroudForge's own starter mod
  (`docs/examples/starter-mod`), byte for byte.

## Not yet seen in a real game

- Gear Up itself has not been added or run: its archive's file list is not on Nexus, and nobody here has downloaded it.
  If priorityPick has another shape, the new message says which field it is.
- The group headings and the "Group: Label" combo items on the in-game page were checked against Kiln's fake UI in
  tests, not drawn in a game.

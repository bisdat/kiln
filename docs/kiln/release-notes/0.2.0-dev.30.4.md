# Kiln 0.2.0-dev.30.4

A small patch for 0.2.0-dev.30.3: kiln mode starts again. Kiln's interpreter for ShroudForge mods was refused at every start in 0.2.0-dev.30.2 and 30.3, so no ShroudForge mod ran in kiln mode. Kiln's bundled ShroudForge, the default, was not affected.

**Not checked in a real game yet.** Both fixes passed Kiln's tests, including a Windows test with the real files. If something looks wrong, tell us on GitHub or Discord with `kiln/logs/launcher.log` or `kiln/logs/kiln.log`.

## Players

- **Kiln mode starts.** In 0.2.0-dev.30.2 and 30.3, Kiln turned its own interpreter away at every start: the interpreter's file was missing the build mark Kiln checks before it hands it the ShroudForge mods (`kiln.log`: "not the ShroudForge-dialect owner"). So none of kiln mode's 30.2 and 30.3 additions could run in a game. Kiln mode starts now, and Kiln's release checks refuse a build where that mark is missing or differs.
- **Switching to kiln mode after the bundled ShroudForge.** When you switched from Kiln's bundled ShroudForge to kiln mode, the start stopped at the game data the bundled ShroudForge had prepared (`kiln.log`: "the live enshrouded.kfc is neither the BASE nor output Kiln can prove it published"), and no ShroudForge mod ran. Kiln now puts the game's own data back when it can prove what the bundled ShroudForge wrote. When it can't, it tells you to verify the game files in Steam (Properties, Installed Files) and then start the game again from the Kiln launcher.

## Coming next

The next launcher update installs the matching Kiln by itself after the launcher restarts, when the game is closed.

# Kiln 0.2.0-dev.31.28

Map icons that mods place with Kiln.Markers now stay on the world map in every frame, at any frame rate. Before, they
showed in some frames and not in others whenever the game ran faster than 60 fps.

## Players and server admins

- **Mod markers on the world map no longer flicker.** The game rebuilds its list of map markers in every frame. Kiln
  added the mods' icons only at the game's 60 steps per second, so above 60 fps the frames in between had no mod icons
  and they blinked. Kiln now puts them back after every frame's rebuild. The game's own markers were never affected,
  and neither were Kiln's compass strip and labels in the world.
- **Thanks** to cykel-far for the report and the careful reading of the code that pointed at the map list (kiln#159).

## Modders

- No mod API change: mod API 0.2.26, as in 0.2.0-dev.31.27, and no signature or enum change. The MDK packs are
  0.2.0-dev.31.28. `MarkerSurface.Map` works as before; nothing to change in a mod.
- **The cause.** The client world steps once per frame: on frames without a new 60 Hz step the game still calls SimStep
  (with ticked 0), and SimStep still runs clear_map_markers_for_ui and replicate_map_markers_for_ui, which empty and
  refill the map list. Kiln's client Post runs only at ticked steps, so on the other frames the map was drawn from a
  list without Kiln's rows. It was not a race inside a step: the Post did run right after the refill, but only at the
  frames that had a new 60 Hz step (60 of 144 at 144 fps). The map's marker layer is rebuilt whenever the list's count
  changes, so each frame showed or dropped the icons. Static analysis of client 26430625 in docs/re/map.md, "The list
  in a frame".
- **The fix.** kiln.markers keeps the rows its last Post wrote and writes them again after every client SimStep
  returns, from a kiln.hooks link on SimStep that runs around the core's own (label `markers/SimStep`). By then the
  client world's step has waited for its jobs, and the UI frame that reads the list runs outside SimStep on the same
  thread, so it never sees the list between the refill and Kiln's rows. The same guards and room rule apply: the
  game's own rows are never pushed out, and a row that has no room is left out. At a ticked step the link finds the
  Post's rows at the list's end and writes them over in place, so they are never there twice.
- **The icons follow the Post.** A marker that moves or is removed changes on the map at the next Post, at most one
  60 Hz step later, as on the compass strip and the world labels, which draw the Post's snapshot. A world that stops
  takes its icons with it. If the client Post itself stops (the core removes a tick subscriber that faults), the kept
  icons are dropped at the next 60 Hz step, so they never stay on the map without it.
- **New sigdb feature `markers.client_map_steps`** (client only): the core's `SimStep`, `world.storage` and
  `storage.kind`. If it does not resolve on a game build, the icons are written at the Post only, as before, and
  kiln.log says once at start "markers: the end of each client step cannot be found on this build
  (markers.client_map_steps): map icons are written at the client's 60 Hz steps only and can flicker at a higher frame
  rate". If kiln.hooks refuses the link, the line starts "markers: the link after each client step could not be
  installed" and names why. When it works, kiln.log says "markers: map icons are written again after every client step
  (markers.client_map_steps)".
- Host tests over a fake map list in the game's order (clear and refill every frame, Kiln's Post at the 60 Hz steps,
  the UI read after each): at 144 fps every read has the game's rows and Kiln's after them, and the kept rows follow
  the last Post, stay in their world and end with the Post (`surfaces_test`).
  `tools/sigport/tests/test_markers_map_steps.py` pins the static facts on the client exe.

## Not yet seen in a real game

- Nobody has opened the map with this build yet. The fix rests on static analysis and host tests; cykel-far offered to
  test a dev build in single player.
- A marker that moves (one that follows an entity) while the map is open: the map keeps pointers to the list's slots
  and Kiln writes its slots again at every step, so it should move as before, but that was not watched.
- The frames the game skips its world step entirely (a paused world: a byte the client world update checks, which the
  game's frame loop sets; its meaning was not followed further): the list then keeps what the last step left, Kiln's
  rows included.

# Kiln 0.2.0-dev.31.next (assets-hash part; work-cm renames and merges this file)

## Modders

- No mod API change (a doc comment of `kiln_assets.h` and of TestKit's `FakeBlobRegistration.Hash` only).
- **kiln.assets reads a blob's `hash` exactly.** In `assets/assets.json` a blob entry's `hash` is the text `ContentHash.ToString()` writes, `<decimal size>-<h0>-<h1>-<h2>`: the size in decimal, each word 1 to 8 hex digits, nothing before, between or after. Any other `hash` (a size in hex, a space or sign, a value that is not a string) is now an error of that entry, `blob <file>: bad hash … (want <decimal size>-<h0>-<h1>-<h2>)`, and a file of another length than the hash says is one too, `blob <file>: its hash says <n> bytes, the file has <m> (the size is decimal)` (it was `blob <file>: failed`). The manifest's other entries still load. Up to 0.2.0-dev.31.21 a hash kiln.assets could not read was served under the hash it derives from the file's bytes, with "errors 0", and the game then found nothing under the hash the mod named ("Could not find content"). `Assets.Dump("blob:…")` reads the same text.
- `kiln lint` flags such a hash as KL106 (now also a size of more than 10 digits) and a size that is not the file's as KL504.
- `kiln-vfxcook cook` writes its `assets.json` blob hashes in that spelling; they had the size in hex. Its file names and report keep the cook's own all-hex spelling.

## Not yet seen in a real game

- A mod whose `assets.json` has a blob with a bad hash, in a game or on a server: host tests of the entry's rule and the Windows build only.

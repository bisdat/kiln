# Kiln 0.2.0-dev.31.next: Kiln's overlay next to NVIDIA Streamline, if you choose it (Soligna, Nexus 301)

## Players and server admins

- **Draw Kiln's overlay anyway, from the launcher.** When an NVIDIA Streamline frame generation mod is in the game folder (`sl.interposer.dll` there or in `Streamline/`), Kiln turns its in-game overlay off by itself, because the two together crashed the game at start in 0.2.0-dev.29. Every HUD mod went with it, Grimoire's for one. The only way to draw it anyway was the launch option `KILN_UI_OVERLAY=1`, which Steam cannot set on Windows. Now the launcher's Play page shows NVIDIA Streamline with a switch under it: **Draw Kiln's overlay anyway (may crash at start with frame generation)**. Settings, Graphics has the same switch under the lines at its top. It applies from the next game start, and switching it off gives the choice back to Kiln. The switch is also there next to OptiScaler when its own menu or its frame generation keeps Kiln's overlay off.
- **By hand, on Windows and Linux:** in the game folder's `kiln/kiln.json`, put `"overlay": "on"` in the `"ui"` section, for example `{ "ui": { "overlay": "on" } }`. Exactly `"on"`: anything else lets Kiln decide. `"off"` and `"auto"` work as before. Settings, Advanced, Kiln's file now offers all three under "Kiln's overlay". On Linux, `KILN_UI_OVERLAY=1 %command%` in Steam's launch options still does the same, and wins over the file; `KILN_UI_OVERLAY=0` still keeps the overlay off whatever the file says.
- **What it risks.** "on" does exactly what `KILN_UI_OVERLAY=1` does. Kiln still records each start: if the game closes while the overlay is starting, the next start says so in `kiln/logs/kiln.log`. But while the switch is on, Kiln tries the overlay again at every start. **If the game keeps closing at start, switch it off**, in the launcher or by removing the line. Kiln then steps aside again by itself, and its record of those starts still counts: after two closes at the same stage it keeps the overlay off until you delete `kiln/state/overlay-start.guard`, switch it on again, or update Kiln.
- **Only the overlay.** Kiln's frame cap, DLSS settings and upscaler still step aside for Streamline and OptiScaler. The readout draws, since it is part of the overlay.
- **The Mods entry names the setting.** With the overlay off for Streamline or OptiScaler, the game menu's Mods entry now reads, for example, "Mods: the overlay's drawing is off: NVIDIA Streamline is installed (kiln.json ui.overlay "on" draws it anyway)". kiln.log names whichever switch decided.
- **Thanks to Soligna** for the request (Nexus 301).

## Modders

- No mod API change: mod API 0.2.26, as in 0.2.0-dev.31.24.
- **kiln.json `ui.overlay` takes `"on"`** next to `"off"` and `"auto"` (`native/services/ui/overlay_setting.h`). It is `KILN_UI_OVERLAY=1` in the player's file: what wins is `KILN_UI_DISABLE=1`, then `KILN_UI_OVERLAY` set to `0` or `1`, then kiln.json, then Kiln's own decision (the crash guard, Streamline, OptiScaler). The crash guard is the same for both switches: the attempt is recorded before Kiln's first Vulkan hook, a death in it is counted at the next start (guarded, then locked at a second one at the same stage), and that start draws again while the switch is on. A host test runs one sequence with each switch next to Streamline and requires the same records at every start.
- **`Ui.Status.Error` and the drawing capability rows** for Streamline and OptiScaler now end with "(kiln.json ui.overlay "on" draws it anyway)", as the Mods entry does. A mod that compared the whole text should match its start instead.
- **Expected with frame generation, not yet seen:** when Streamline's present thread presents through Kiln's hook, draw and pre-overlay callbacks run on that thread, once per frame shown (generated frames too), not once per frame the game renders.
- **Launcher:** the kiln.json snapshot's `ui.overlay` has the options auto, off and on; `components/OverlayAnyway.tsx` writes `"on"` and resets the key when switched off. kiln-manage's OptiScaler note (Play page, support report) names the switch instead of the launch option.

## Not yet seen in a real game

- Kiln's overlay with "on" next to a Streamline frame generation mod: nobody has run it yet. From Streamline's SDK and Kiln's code, where Kiln draws depends on how the mod loads Streamline. When Streamline stands in for the game's Vulkan loader, Kiln draws on every frame shown, generated ones included: sharp, but once per shown frame, inside Streamline's frame pacing. When Kiln's hooks end up in front of Streamline, Kiln draws on the game's own frames before frame generation, and its windows may wobble in the generated frames, as the game's own HUD can. When Streamline presents from a queue Kiln saw it add under it, Kiln draws nothing for that session, and kiln.log says "frame generation presents the game's frames from its own queue". The cause of the 0.2.0-dev.29 crash at start was never confirmed. A tester with an RTX 40 or 50 card and the mod can tell which case it is from kiln.log and the readout's frames a second.
- The launcher's switch: tests in the launcher's preview (mock) mode only.

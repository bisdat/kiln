# Kiln 0.2.0-dev.31.next (soft-range part; work-cm renames and merges this file)

## Players

- **A mod's setting can go past the end of its slider when the mod allows it.** On the Kiln menu's config page and in the launcher, a setting whose mod marks that end of its range as soft (for example a cost multiplier with a slider from 0 to 1) now takes a typed 2 or 3 in the number field beside the slider, and a value like that in the config file is kept instead of being clamped back with a warning. The slider stays at its end for such a value; dragging it gives a value of the slider's range again. Settings whose mod did not mark a soft end work as before. Thanks to fafawanji for the request (#155).

## Modders

- **Soft range sides for configs: `[Range(0, 1, 0.1, SoftMax = true)]` (#155, mod API 0.2.26).** `RangeAttribute.SoftMin` / `SoftMax` (named arguments) make that side end the slider only: a value past it, typed into the number field, read from the file, set with `TrySet` or sent by a server, is kept as it is, with no refusal, no clamp and no warning; only the number's own type still bounds it. The other side stays hard as before (a typed -1 is refused with `"costMultiplier" must be in 0..max (got -1)`, a -1 in the file is clamped with the usual warning). `ConfigEntry.SoftMin` / `SoftMax` and the live and offline schemas' `softMin` / `softMax` (written only when true) carry it; the file's meta line reads `Range: 0 .. 1 (slider; higher values allowed)` (`Range: 1s .. 1m (higher values allowed)` for a duration or a list, which have no slider). Durations and lists of numbers follow the same rule, a `[Command]` argument has no bound on a soft side, and a UI block's `set` action or slider `min` / `max` may go past it. A `decimal` entry is bounded by the decimal type there (about ±7.9e28). The step stays the third argument: `Step = 0.1` as a named argument cannot compile (`Step` is a `double?`, which C# does not take as a named attribute argument), so write the step positionally. A mod that uses the flags needs mod API 0.2.26, which the 0.2.0-dev.31.22 SDK writes into its manifest. Thanks to fafawanji for the request (#155).
- Mod API 0.2.26 (was 0.2.25): additive only, `RangeAttribute.SoftMin` / `SoftMax` (get, set) and `ConfigEntry.SoftMin` / `SoftMax` (get, init).

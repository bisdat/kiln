# Kiln 0.2.0-dev.31.next: spell picker flicker (GitHub issue 151)

## Players and server admins

- **A mod's spell or arrow no longer flickers back to the previous one after you pick it.** With a mod that puts its own spells or arrows in the HUD list (Grimoire, for example), the picker moved to the spell you picked, showed the spell you had before for a moment, then went back. The game keeps putting the list's cursor on the equipped spell until the mod's swap of the new spell arrives, a short moment when you play alone (longest in the first switches after a start) and a network round trip on a dedicated server. Kiln now keeps the cursor on your pick until the swap arrives, for up to a second. On a dedicated server the next scroll step also starts from the spell you picked, not from the one still equipped. Thanks to Fuzen777 for the report and the trace from Grimoire (#151).
- **New for testers: a pick trace in kiln.log.** Put `{ "ui": { "ammoTrace": true } }` in `kiln/kiln.json` (or set `KILN_AMMO_TRACE=1`) and start the game. For 2 seconds after each pick of an arrow or spell row, kiln.log then shows the pick, the game's selection, each build of the list and what the HUD drew, frame by frame (lines `ui.ammo trace: ...`). It is off by default. How to read it: [docs/kiln/ui.md](../ui.md#tracing-a-pick-of-the-list-testers).

## Modders

- No mod API change. The cursor of a `Ui.AmmoList` row's pick (`Picked`) now stays on that row over the game's selection sync, which put it back on the equipped item because such a pick writes no pending pick of the game's. It holds until the game itself selects that item (your server half's swap arrived), the player picks a row that goes to the game, the list is cleared, the provider retires, the session changes, or 1 s passes. This applies in `Append` and `Replace`, only while your rows are up. When your new rows no longer list the item under the cursor, the list takes the game's own selection instead of none (the HUD used to draw the index it drew last). The test kit's `KilnHarness.AmmoList` already kept `Selected` on the picked item. Thanks to Fuzen777 (#151).
- The opt-in pick trace above names, for each pick, where it came from and who took it, the game's choice in its selection sync and in each build, which rows the build showed (the current publication, rows kept over a newer build, or the game's own and why) and the index and item the HUD drew. A step writes a line only when what it saw changed, at most 100 lines a second.

## Not yet seen in a real game

- The picker with Grimoire's nine spells, alone and on a dedicated server: host tests over fakes of the game's selection sync, list build and draw, plus static reads of client 26430625, only.
- Which of the game's selection sync, list build and HUD draw runs first in a frame, and so on how many frames the previous spell was drawn. The trace's `sync`, `build` and `draw` lines show it.

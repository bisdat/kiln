# Kiln 0.2.0-dev.30.7

A patch for 0.2.0-dev.30.6. Mod API 0.2.16 adds player storage (Fuzen777's request): mods can give players bags, quivers and spellbooks of their own that are saved with the character, protected against item loss and duplication, and kept safe when Kiln or the mod is removed. Kiln now has its own Unlimited Flight (`/unlimitedflight`). Kiln tasks are no longer experimental. Building tools from Kiln mods show their brushes in the game's brush picker. Fixes for a blank launcher on Linux with NVIDIA, ShroudForge mods that walk very large game assets, a stale ShroudForge backup, and saving support reports on the Steam Deck.

**Not checked in a real game yet.** Everything passed Kiln's tests, on Windows where it matters. If something looks wrong, tell us on GitHub or Discord with `kiln/logs/launcher.log` or `kiln/logs/kiln.log`.

## Players

- **Unlimited Flight, built in.** As the host or a server admin, `/unlimitedflight on` gives your own glider unlimited stamina and S/W steering (S climbs, W dives), without Creative Mode. `/unlimitedflight off` turns it off, `/unlimitedflight status` shows what works here. Off by default, and the server's `rules.json` limits still apply.
- **Player storage from mods.** Mods can now give you storage of their own (an extra bag, a quiver, a spellbook) that is saved with your character. Its contents are kept when you remove a mod or Kiln, and come back when you add them again. Your game shows a read-only copy of your own storages, and a quiver or spellbook from a mod can show its arrows and spells in the HUD's ammunition lists. The save editor shows a character's mod storage, and for a local character it can put base-game items back into the character, with an automatic backup; a server that later sees that character holds its own copy instead of handing it back, so nothing is doubled. Admins list and release held storage with `/playerstorage list <player>` and `/playerstorage release <player> <key>`. Thanks to Fuzen777 (#128).
- **Brushes for mods' building tools.** Building tools from Kiln mods now list their own brushes in the game's brush picker (the first 16, in the mod's order), at their declared sizes. If the picker still shows none, `kiln.log` says why. Thanks to bisdat (#130).
- **Building tools with only brushes load.** A mod whose building tool has only brushes or tool material pools now gets its tool items and recipes at startup. Thanks to bisdat (#129).
- **A blank launcher on Linux with NVIDIA recovers.** A launcher that started blank recovers on the next start by drawing through shared memory, remembers what worked and never loops. The switch is under Settings > Advanced > Drawing the launcher.
- **ShroudForge mods.**
  - Mods that walk very large game assets (for example Forged and Found 0.16.1) no longer stop startup with "cannot create a Lua reference, out of auxiliary stack space". Thanks to Somamint.
  - A stale or incomplete game-data backup is never restored over your current game files, and restoring the backup pair can be undone if it stops halfway.
  - An installed ShroudForge app older than the one Kiln runs no longer opens its broken Modloader and World Editor windows; `kiln.log` says to update it, and mods still load. If the app's version can't be read, its windows open as before, with one `kiln.log` line saying they may fail if the app is old.
  - EML mods whose manifest leaves optional fields empty load.
  - When ShroudForge's startup pass fails inside, `kiln.log` has one plain line naming the mod that was running.
- **Support reports on the Steam Deck** can be saved straight to Downloads, with fallbacks when the Save dialog fails. Reports now also say when a ShroudForge mod is older than the copy Kiln brings.
- **EMF mods in big bases.** Kiln lists entities 5 to 12 times faster for EMF mods, and `kiln.log` says when an EMF mod costs the server more than 2 ms per step, and what it does each step.

## Modders

- **Mod API 0.2.16.** Mods built for 0.2.16 need this Kiln; mods for 0.2.15 and earlier keep working.
- **Player storage (#128).** `Items.RegisterPlayerStorage(key, slots, filter, death)` gives each player a storage of your own, saved with their character (`PlayerStorage`, `PlayerStorageInfo`, `Items.PlayerStorages.Of`, `ReturnOrphans`). Contents a player can't use right now are parked, never dropped (`PlayerStorageParkReason`: `Unregistered`, `Overflow`, `Filter`, `Requested`, `Stale`, `Locked`, `ReturnedOutsideKiln`), and come back when the storage registers again; events `PlayerStorageParkedEvent`, `PlayerStorageRestoredEvent`, `PlayerStorageDeathEvent`, `PlayerStorageClientChangedEvent`. A quota of 32 eight-slot pages per player, at most 64 parked items per storage (more go to quarantine). The client copy is trusted by default, with a per-server switch (`storage.trustClient` in `kiln/config/characters.json`). Check `PlayerStorage.Available` before registering. The player's own game gets a read-only copy over channel `kiln:storage` (`PlayerStorage.Client.Rows`, `PlayerStorageClientChangedEvent`); `PlayerStorage.Client.ProvideAmmo` shows a storage's arrows and spells in the HUD's ammunition lists (`Ui.AmmoList`) and equips a pick on the server, and `PlayerStorage.Activate` swaps a stack into the backpack as a fallback; `QuiverSample` shows it all. Item mod data of parked items is kept as long as they stay parked; one player's storage problem no longer stops a world's mod data from saving (`Saves.PlayerStoragePersistenceFailure`, `CharacterSettings.Storage`, `PlayerStorageSettings`). Native: new table `kiln.items.storage` v1. TestKit fakes included. Thanks Fuzen777.
- **Kiln tasks are normal API.** Task-thread world reads and compare-exchange writes (`WorldConcurrent` and its types) and TestKit's `FakeWorld.BusyReads`/`BusyWrites` are no longer experimental: no `KILNX003` opt-in is needed (an existing one is harmless). Threading, bounds and capability checks are unchanged.
- **Content blocks are checked like the schema and `kiln lint`.** Values that 30.6 loaded without harm still load, with one warning per block in `kiln.log` and in `kiln blocks`; lint reports them as errors, so please fix them. Still refused, because they made the game misbehave: a hit clip with speed 0 or below, a blend position that isn't a finite number, and an attack or cone angle that isn't a number.
- **Behaviour change (Kiln.Blocks):** a creature attack's `angle` above 179 is no longer narrowed to 179: 180 to 359 reach that wide, 360 all around, and a 360° cone that affects friends includes the caster. Check creatures that set a wide angle.
- **Building tools.** Tool-only `blocks.tables.json` files load at startup (#129); the `"blueprints": {}` workaround is no longer needed. A required mod whose own tool-only blocks file is malformed is now refused with a clear error. Brushes appear in the picker with their impact config's radius, item tags resolve against the registry's tag list, and `terrainVoxelObject` resolves as a terrain voxel model (#130).
- **EMF.** `for_each_entity` / Lua `world:entities()` are 5 to 12 times faster in large bases. `state/emf.json` has a per-mod `cost` block, and `kiln.log` names a mod that costs over 2 ms per server step.
- **Docs.** The API reference at https://frostdev.io/kiln/api/ is themed like the wiki, loads much faster and has a name search; nearly every public member has XML docs, each says which release added it, and the kiln-modding agent skill has a generated API index.

## Not yet seen in a real game

- Player storage end to end: holders and pages staying out of the world save across a save and restart; paired join, save, leave, death and offline return; firing from a quiver storage debits exactly one arrow; HUD ammo rows from storage; item mod data across a park and restore; the game accepting a character file the launcher's return rewrote.
- Kiln's `/unlimitedflight` glide and steering on hosted and dedicated worlds.
- Mods' brushes in the brush picker, and Kiln brushes carrying `equipment.terrainVoxelObject` while stroking.
- The NVIDIA blank-launcher recovery on real hardware (Wayland and X11), the Steam Deck's real Save dialog, and the ShroudForge backup restore across a real game update.
- Forged and Found 0.16.1 starting with the ShroudForge Lua fix.

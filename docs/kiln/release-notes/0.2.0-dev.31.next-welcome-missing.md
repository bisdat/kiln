## Players and server admins

- **Hosting your own world no longer reports your own mods as missing.** When you joined a world you host, kiln.log listed your ShroudForge, Flame and other non-Kiln mods as "missing" (for example `welcome from srv-…, missing creative, altar-cleanup, …`), although your game was running them. Your own hosted world now never lists anything as missing. On someone else's server, the list of missing mods now also checks the ShroudForge, Flame, Green Eye and SET mods in your game folder, not only Kiln and native mods. It compares each mod the way the server advertises it, so its logs and your settings don't count as a difference. A mod you have switched off still counts as missing, because the server needs it running. EML mods, EMF's DLL mods and Shroudtopia mods that Kiln runs from your Library are not checked yet, so they can still show up as missing. kiln.log names the side: `welcome from your hosted world (srv-…, this game), nothing missing`, or `welcome from server srv-… "Name", missing … (this game lacks them, has them switched off or has another version)`. The launcher's Play page no longer offers a modpack for your own hosted world, also after a join recorded by an older Kiln.

## Modders

- `kiln/state/last-server.json` gains `hosted` (boolean): true when the answer came from this game's own hosted world, and then `missing` is empty. Kiln writes it as true or false; only an older file leaves it out, and the launcher then compares the server id with the game's own. In other answers `missing` now covers other engines' mods in the game's engine folders too, each compared by the hash the server advertises (`AdvertiseIdentity.cs` rules); a copy that is switched off (ShroudForge's `enabled: false`, or `targets` without `client`) is missing. No API change.

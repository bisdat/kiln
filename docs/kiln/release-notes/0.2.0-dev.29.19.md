# Kiln 0.2.0-dev.29.19

This patch brings Kiln in nine more languages and runs mods for AndyPimms' Enshrouded ModLoader (CarryOn, Belt Lantern) without that loader. Kiln's line in the main menu makes room for XHL-Core's warnings, and station screens count the finished items other stations lend (GitHub #68). AMD FSR now runs on AMD graphics cards, with a new try at FSR 4's dark scenes. The Linux launcher draws with the GPU's compositing again, kiln.log warns before the game's impact memory runs out, and support reports include more mods' logs. A new SDK (mod API 0.2.11) brings Kiln's language and key presses for mods and hooks inside another mod's DLL, and for native plugins resident tasks and the game's original code. Everything else is as in 0.2.0-dev.29.18.

**Not all of it checked in a real game yet.** This patch passed Kiln's tests, and its test builds passed the release's own checks. In a real game, a tester with an AMD RX 9070 XT saw AMD FSR 4 run on this patch's test builds, with dark scenes drawn far too dark. This release's change for those dark scenes has not been seen on an RX 9000 card yet. Not seen in a real game yet: mods for Enshrouded ModLoader in Kiln, Kiln's main menu line with XHL-Core, the station screens' counts and fill buttons with station outputs, the nine new languages in the game, a mod's hooks inside another mod's DLL, the impact memory warning, ShroudLink's lighter chest-name scan, and the Linux launcher with compositing on a PC where the old start-up error happened. If something looks or works wrong, tell us on GitHub or Discord with `kiln/logs/kiln.log`.

## Players

- **Kiln in nine more languages: Deutsch, Español, Français, Italiano, 日本語, 한국어, Polski, Português (Brasil) and Русский.** The whole launcher and all of Kiln's own texts in the game. They are machine translations: complete, but not yet read by native speakers. If one of them is your language, its review issue on GitHub says what to look at first (#90 German, #91 Russian, #92 French, #93 Spanish, #94 Brazilian Portuguese, #95 Japanese, #96 Polish, #97 Italian, #98 Korean). A comment there or a pull request is all it takes. Choose a language as for Simplified Chinese: in the launcher's Settings, Language (on a Steam Deck the Language row of Settings), and in the game in Mods &gt; Kiln settings &gt; Language. "System" and "Same as the game" (the defaults) pick them by themselves. Russian and Polish plurals now read right in the game. Kiln's overlay draws Cyrillic with the game's own Cyrillic font (Kiln ships no font). Until that font is loaded, Kiln's texts in the overlay stay English rather than question marks. Not yet checked in a real game. Details: [translating.md](../translating.md).
- **Mods for AndyPimms' Enshrouded ModLoader run in Kiln.** CarryOn (move chests with their contents, furniture, doors and wells), Belt Lantern (a lantern equipment slot) and other mods made for Enshrouded ModLoader: add the mod's zip in the launcher and switch it on. You don't need that loader's `dinput8.dll`, and you don't run its `Install.cmd` for Kiln. Kiln starts the mods when a world of your own starts, as the loader does. Game client only, on game build 26430625, in single player and when you host. As with the loader, the mods start once per game session, for one world: another world needs a restart of Enshrouded, and joining another player's world with them on is refused with a message. A mod that cannot start keeps the world from starting, with a message box that names it, because a world opened without it can lose that mod's items when it saves. A mod's settings come from Kiln's file for it (`kiln/config/dllmod/<id>.ini`), else from what the loader saved for that world, else from the mod's defaults. The launcher has no settings page for them yet. Kiln's in-game Mods page lists them with their state. With Enshrouded ModLoader installed too (its own `dinput8.dll`, or since ModLoader 0.6.15 as a Kiln native module), Kiln steps aside and leaves its mods and its files to it. Such a mod's DLL is also never imported as a plain DLL mod any more: loaded that way, the loader refused every world with it. Not yet checked in a real game. Details: [engines/dllmod.md](../engines/dllmod.md).
- **Kiln with XHL-Core.** With XHL-Core in the game, Kiln's line in the main menu now reads "Kiln 0.2.0-dev.29.19 with XHL-Core - N Mods Loaded". While XHL-Core reports a problem, its red line ("XHL: Game updated · Click to view", "Mod conflict detected. Click to view") shows under Kiln's again, in XHL-Core's words and colour. A click, the keyboard or a pad opens XHL-Core's diagnostics, as without Kiln. Before, Kiln's line took the place of XHL-Core's. XHL-Core's green "All mods loaded" is left out, as Kiln's line says that XHL-Core runs. Where Kiln cannot read XHL-Core's state, XHL-Core's line is always drawn, so a warning is never hidden. Not yet checked in a real game. Details: [ui.md](../ui.md#kilns-line-in-the-main-menus-footer-since-020-dev2911).
- **XHL's mods in the Library.** When the Kiln build of one of XHL's mods and his XHL-Core plugin of the same mod are both on, with XHL-Core in the game, the mod runs twice. Applying the profile now says so for each such pair and asks you to switch one of them off. It changes nothing by itself. A ShroudForge mod with a `native-plugin.ini` that XHL-Core would not run (Unified Tweaks, for example) is a ShroudForge package again, in the Library and on the in-game Mods page, not an XHL-Core plugin. Details: [engines.md](../engines.md).
- **Station screens count station outputs (GitHub #68).** Since 0.2.0-dev.29.17 a mod can let a production station lend its finished items to its base (`Stations.SetOutputSource`: charcoal still in a Charcoal Kiln, say). On a Kiln client with a Kiln server, a production station's "+1" and "+10" fill buttons now light up when those items cover the fill, and pressing them fills from them. The server checks every press again. The ingredients' "Available" counts, on the station screen and in the crafting menu, include those items too. A game without Kiln keeps the game's own buttons and counts, and other screens (building costs) keep the game's counts. It needs a mod that opts a station in. With Creative Mode running, Kiln's crafting-menu counts stand aside. Not yet checked in a real game. Details: [services/stations.md](../services/stations.md#the-station-screens-fill-button).
- **AMD FSR runs on AMD graphics cards.** In 0.2.0-dev.29.18 the game's own FSR 3 ran on every AMD card instead of Kiln's AMD FSR: AMD FSR needs one AMD graphics feature that Kiln did not pass on to the game's graphics device. Kiln passes it on now, so AMD FSR runs there: FSR 4 where your card and driver run it (AMD's own choice), else FSR 3.1. Seen in a real game on an RX 9070 XT. Details: [graphics.md](../graphics.md#behind-the-games-fsr-3-phase-b).
- **AMD FSR 4 in dark scenes, a new try.** On this patch's test builds, FSR 4 drew dark scenes far too dark on an RX 9070 XT. The game gives its upscaler no exposure value, so AMD FSR now measures the picture's exposure itself, as AMD recommends. FSR 4 also runs its quality network instead of its dynamic-resolution one, and gets the inputs OptiScaler gives it: a pre-exposure of 1, no reactive or transparency mask, and the camera planes swapped for the game's inverted depth. FSR 3.1 keeps the game's values. AMD FSR's "Auto" still runs FSR 4 where AMD's selection picks it. This change is not yet confirmed on an RX 9000 card. If dark scenes still look too dark for you, choose FSR 3.1 under **AMD FSR version**, on the Kiln menu's Graphics tab (Insert) or on the launcher's Settings &gt; Graphics card. For testers: a file `kiln/control/amd` in the game folder takes one setting per line, to compare each part (`exposure`, `preexposure`, `reactive`, `transparency`, `masks`, `dynres`, `planes`, `hdr`, `colour`). kiln.log's AMD FSR set-up line names what FSR gets. Details: [graphics.md](../graphics.md#upscaler-behind-the-games-fsr-3-how-it-works-020-dev2918).
- **A new upscaler choice applies at once.** Choosing another upscaler while a world runs with FSR 3 now applies at the next frame. Before, the choice waited for the game to set FSR up again, which the game does not do for every quality change (native AA, for example), so AMD FSR could stay "ready" until a world load. A choice that needs a game restart (the game started with its own FSR 3, and you then chose AMD FSR or Intel XeSS) now says so first: "Restart the game to use AMD FSR" leads the readout, sits right under the choice on the Graphics tab, and leads the launcher's Graphics card and the Deck's row. Details: [graphics.md](../graphics.md#behind-the-games-fsr-3-phase-b).
- **Linux: the launcher draws with the GPU's compositing again.** Up to 0.2.0-dev.29.18 the launcher always turned WebKit's DMA-BUF renderer off, against a start-up error seen on GNOME with NVIDIA cards ("Gdk Error 71"). That also turned WebKit's compositing off, so every change was painted again on the CPU, and large windows lagged. It is on again by default, so the launcher stays smooth in large windows. If a start with it ends early, the next start goes without it by itself, says so in launcher.log, and remembers it. If the window stays empty, the launcher tries again without the DMA-BUF renderer first, then without the GPU. Turning Settings &gt; Appearance &gt; "Draw the launcher without the GPU" off tries the default again. `--no-dmabuf` or `KILN_LAUNCHER_DMABUF=off` skips it for a start. launcher.log and the support report say what was chosen and why. Details: [app.md](../launcher/app.md#drawing-without-the-gpu-linux).
- **A lighter launcher behind its pages.** Behind an open page the fire now draws only the header band, not the whole page under it. Where WebKit draws without compositing, the flames of lit mods and the torch hold still, and the fire on Play draws 15 frames a second. Details: [perf.md](../launcher/perf.md).
- **kiln.log warns before the game's impact memory runs out.** The game keeps every hit and attack in one 16 MiB pool per world. When the pool is full, new hits fail, the world slows down and the game can crash. A player's two-hour session ended that way. Kiln now watches the pool. It only reads it and changes nothing in the game. kiln.log warns the first time the pool is 50, 75 and 90 % full in a session and names the five programs that fill it most. At 75 % it also lists the oldest hits still alive. `kiln/logs/tick-stats.jsonl` carries each world's fill. A file `kiln/control/impacts` with `dump` lists it once, and `off` turns the watch off. Details: [services/abilities.md](../services/abilities.md#impact-memory-watch).
- **ShroudLink's chest-name scan stays out of the game's way.** With ShroudLink's assistants mod on, a busy area stuttered at every scan on a PC with four threads and the page file on a hard drive: every 15 seconds the scan read all of the game's memory. A scan now reads only the memory the game holds in RAM, runs in Windows' background mode, and rests between short steps. A scan the game waits for (a chest name it does not know yet) does not rest.
- **One download with a game copy and a server copy.** Some mods (Town Portals, for example) ship a copy for the game and a copy for a dedicated server of the same version in one download. Dropping such a download now puts the game copy into your profile, by its client folder, and says so. The server copy stays in your Library for a server. Before, Kiln could take either copy.
- **Discord's own refusals.** When Discord refuses a support report or test results, Send to Kiln support now says so, with Discord's reason, instead of "frostdev.io isn't answering". When Discord asks Kiln support to wait, the launcher says when to try again. Your draft is kept. Details: [discord.md](../launcher/discord.md).
- **Open in Discord opens the app.** "Open in Discord" on your support posts, your test results and the Community page opens the Discord app when it is installed, the browser otherwise.
- **The overlay's crash guard starts fresh after an update.** A lock an older Kiln left after two failed overlay starts kept the overlay's drawing off after an update, also when the update fixed the cause. The guard's record now notes the Kiln version that wrote it. A record of another version, or one an older Kiln wrote, starts fresh, and kiln.log says so. Details: [ui.md](../ui.md#overlay-startup-crash-guard).
- **Support reports and logs that help more.** The support report now includes Building Tools' (`BuildingTools.log`, `BuildingTools.prev.log`), ShroudLink's (`shroudlink.log`) and Auto Loot Plus' (`auto-loot-plus.log`) logs from the game folder: the last 192 KiB of each, with your paths and names taken out as in Kiln's own logs. kiln.log's lines about another mod's hook now name that mod's file after the module's name, for example `xhl.dll+0x4410 [mods/xhl/xhl.dll]`. Details: [support-report.md](../launcher/support-report.md).
- **No Nexus Mods choices in builds without Nexus Mods.** Kiln's builds ship with Nexus Mods switched off for now. A mod's Updates dialog there now offers only GitHub. A Nexus Mods source you saved before stays saved, with a note that this build does not check it. The daily update check's hint no longer mentions a Nexus Mods sign-in.
- **Smaller fixes.** Kiln no longer stops starting when `kiln/state/boot.json` would hold a byte that is not UTF-8. A deeply nested `"unloadAtExit"` in `kiln/kiln.json` no longer crashes the game at start. On Windows the EML report names a placed mod folder as the launcher spelled it. The default rule presets are written with LF line ends on Windows too, the same bytes as on Linux. The Servers page's line for a stopped server reads right again ("Stopped. Press Start to run it.").

## Server operators

- **A paused world is not a stall.** A single-player world stands still while the game's menu is open, and its clock goes on from where it stopped. In `kiln/logs/tick-stats.jsonl`, gaps of a second or more that the server world's clock did not cover now go into a new `paused_ms` field (count, total, max), written only when there was one, and no longer into `interval_ms`. A player's report read three menu pauses of 10 to 17 seconds as stalls.
- **Impact memory on servers too.** The impact memory warning above runs on dedicated servers as well, and each world's minute line in `tick-stats.jsonl` ends with `"impact":{"used_pct":…,"peak_pct":…,"capacity_mib":16,"live":…,"live_peak":…}`. It is absent when the pool could not be read. Details: [services/abilities.md](../services/abilities.md#impact-memory-watch).

## Mod authors

- **The mod API is 0.2.11.** Everything new is additive: no public member of 0.2.0-dev.29.18 was removed or changed. Use the 0.2.0-dev.29.19 SDK and MDK. New in it: `KilnLanguage`, `KeyInput` and `Hooks.Module`.
- **Kiln's language for mods: `KilnLanguage`** (Kiln.Api, mod API 0.2.11). For a mod whose pages sit beside Kiln's and should read in the same language. `Current` is a lower-case tag (`"zh-cn"`, `"en-us"`), `Setting` is `ui.language` as set (`"auto"` or the tag). `OverlayInEnglish` is true while Kiln's overlay shows its texts in English because the language's font is not loaded yet: show English too. `Changed` runs after a change. A handler that throws is logged under its mod, and a mod's handlers are dropped when it unloads. On a dedicated server both values follow its game language. Details: [ui.md](../ui.md#kilns-language-020-dev2916).
- **Key and mouse presses as they come: `KeyInput.Listen`** (Kiln.Ui, mod API 0.2.11). For a mod that reads presses itself: its own "press a key" field, a key it handles by state, a shortcut layer of its own. Each press has `Down`, `Repeat`, `Captured`, `TextInput` and `Mods`, and `Code` and `Chord` as the Keys page stores them. Return true to keep the press from the game. With `KeyListenFlags.Mouse` (the default) the middle and side mouse buttons and the wheel come too. The listener ends when the mod unloads. Where there is no Kiln overlay (a dedicated server) `Listen` returns a listener that is not `Ok`, with a `Reason`, and never throws for that. `KeyInput.PressCode(vk, scan)` gives the code the Keys page stores. An action the player should be able to remap stays a `KeyBindings.Register` binding. Details: [ui.md](../ui.md#key-and-mouse-presses-as-they-come-keyinput-since-020-dev2919).
- **For XHL-Core (Kiln) and other mods that read Kiln's internals by reflection.** The internals XHL-Core (Kiln) 0.1.0 reads stay as they are, and Kiln's tests pin each name and shape, so the published 0.1.0 keeps working. ui.md has a table from each of them to its public member. `ModContext.Owner` stays internal. Hooks and call sites you have found in the game are welcome as proposals for Kiln's API: a GitHub issue naming the game function or data, how to find it, and what a mod would do with it. Details: [ui.md](../ui.md#xhl-core-kiln-from-reflection-to-public-members-020-dev2919).
- **Hooks inside another mod's DLL: `Hooks.Module`** (mod API 0.2.11). For mods that extend other mods, such as a fix for Creative Mode's search. Every hook still goes into the game's own code unless you open a module first. `Hooks.Module("creative.dll")` opens a loaded module by its file name and never loads it. `Hooks.TryModule` is for a DLL that loads later than your mod. `HookModule.At(offset)` turns an offset into an address in the module's code, and `Find(pattern)` / `FindAll` search its live code (a pattern keeps working when the DLL is updated, a fixed offset does not). `Hooks.FindInModule(name, pattern)` does both steps. Kiln pins the module, so it stays loaded until the game exits. Typed hooks (`Kiln.Sigs`) stay the game's. kiln.log names the module and every link in it as module+offset with the module's file, and `kiln/state/hooks.json` lists such a target with `"module"` and `"offset"`. The capability row is `hooks.foreign_modules`. On an older Kiln `Hooks.Module` throws `KilnUnavailableException`. Native plugins get `open_module` and `module_scan` in kiln.hooks. Run in Kiln's hook tests under Wine and natively on Windows, not yet in a real game. Details: [hooks.md](../hooks.md#hooks-inside-another-mods-dll-since-020-dev2919), [services/hooks.md](../services/hooks.md#hooks-inside-another-module-open_module-module_scan-since-020-dev2919).
- **The game's original code for native plugins: `read_original` and `code_state` (pull request #101).** Two members appended to the kiln.hooks v2 table (the version stays 2). `read_original` copies the exe file's bytes at an address, never live memory, so a function that Kiln or another module hooked reads as the game shipped it. `code_state` says whether the live code there is still the file's: `KILN_CODE_ORIGINAL`, `KILN_CODE_MANAGED` (every byte that differs is Kiln's own detour or patch), `KILN_CODE_FOREIGN` or `KILN_CODE_UNKNOWN`, with a generation counter for the whole process. Both take a range inside the exe's `.text` of at most 64 KiB, run on any thread, on a dedicated server and on a client. Capability rows `hooks.read_original` and `hooks.code_state`. Details: [services/hooks.md](../services/hooks.md#original-code-read_original-code_state-since-020-dev2919).
- **Resident tasks for native plugins: `KILN_TASK_RESIDENT` (pull request #100).** A flag in kiln_tasks.h, only together with `KILN_TASK_LONG_RUNNING`, for a body meant to run until it is cancelled, such as a plugin's own service loop. The watchdog does not report it as running too long until its cancellation is asked. Its first start writes one line to kiln.log, and its time adds nothing to `cpu_ms` / `wall_ms` in tick-stats. An owner has at most one resident task. The table's version and size are unchanged, and an older Kiln refuses the flag with `INVALID_ARGUMENT`, so a caller can retry without it. Details: [services/tasks.md](../services/tasks.md#resident-tasks).
- **Station outputs on Kiln clients' station screens.** `Stations.SetOutputSource` now also reaches a Kiln client's station screen and ingredient rows (above). The capability rows `stations.stock_ui` and `stations.fill_ui` say whether they follow station outputs on a client. Their hooks go in only once a Kiln server's craft-stock snapshot is on. Details: [services/stations.md](../services/stations.md#the-station-screens-fill-button).
- **Enshrouded ModLoader packages are the Library kind `dllmod`**, run by `kiln-dllmod.dll` in `kiln/plugins/`. `kiln/state/dllmod.json` holds their state. Details: [engines/dllmod.md](../engines/dllmod.md).
- **kiln.log keeps a mod's whole line when it holds a NUL character**, written as `\0`.
- **The hook map names files.** kiln.log's overlap and foreign-hook lines name the other module's file in brackets (relative to the game folder, `[game folder]`, or its full path), and `kiln/state/hooks.json` carries it as `path`. Details: [services/hooks.md](../services/hooks.md#other-modules-hooks).
- **Kiln.TestKit: `KilnHarness.LogFile` and `ReadLogFile()`** read kiln.log while the harness writes it, which `File.ReadAllText` cannot do on Windows. Details: [modding/unit-tests.md](../modding/unit-tests.md).

## Translators

- **Nine machine translations wait for native speakers.** German, Russian, French, Spanish, Brazilian Portuguese, Japanese, Polish, Italian and Korean, each for the launcher and for Kiln's texts in the game. For each language, `docs/kiln/translations/<tag>.md` gives the choices made, a glossary and what to check first, and GitHub #90 to #98 is its review issue. Details: [translating.md](../translating.md).
- **Plural forms in the game.** Kiln's in-game texts now use `few` and `many` for Russian, Ukrainian, Belarusian and Polish. A form a file lacks falls back to its `other`. The launcher's check script (`bun scripts/i18n-check.ts`) now lets a plural form carry `{count}` where English's `one` leaves it out. Details: [translating-game.md](../translating-game.md).
- **Cyrillic and Thai in the game.** Kiln's overlay now draws Cyrillic and Thai with fonts of the game's own default font group, for every language: Kiln's texts and a mod's. Details: [translating-game.md](../translating-game.md#cyrillic-and-the-other-scripts-of-the-games-default-font-group).

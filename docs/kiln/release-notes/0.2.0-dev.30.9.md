# Kiln 0.2.0-dev.30.9

A patch for 0.2.0-dev.30.8. Kiln's terrain saves stop adding fake Flame Altars and fake base areas, servers can restart and take mod and Kiln updates on their own, "Check now" in the launcher says what it found, and the runtime on Nexus Mods comes as a plain folder. Mod API stays 0.2.16.

**Not checked in a real game yet.** Everything passed Kiln's tests, on Windows where it matters. If something looks wrong, tell us on GitHub or Discord with `kiln/logs/launcher.log` or `kiln/logs/kiln.log`.

## Players

- **Fewer fake Flame Altars (#136).** Kiln's terrain save adds far fewer extra Flame Altars to the world list and no longer creates fake base areas. Before, crafting stations, storage and beds could act as if those areas were bases. Edits inside a base are saved with that base and add nothing. Edits outside every base, or at a base's edge, still get their own save area, which still counts as an altar in the world list. Worlds drop their redundant altars at their next save. Thanks bisdat (kiln#136, PR #137).
- **Big bases keep Kiln's terrain edits.** The game saves at most 4,096 terrain chunks per base. Kiln now gives edits in bases bigger than that (about 240 m and up, as with altar-size mods) their own save area, so they can't be skipped at a save.
- **After a game update.** If Kiln can't find the game's save code after an update, it keeps saving every edit rather than risk losing one, and says so in `kiln.log` and in its capability report.
- **"Check now" says what it found.** About, Settings and the Deck now say "Checking for updates…", then "Kiln is up to date (version) · checked <time>", the version available, or why the check failed. Before, a current launcher looked like nothing had happened. Thanks HadToRegister.

## Server owners

- **Restart from admin tools.** Kiln.Admin can restart the server: a countdown in chat, a save, then a clean stop. Servers run with kilnctl's systemd unit come back on their own. If you use your own unit, add `SuccessExitStatus=75` and `RestartForceExitStatus=75`.
- **Staged updates.** Mod and Kiln updates can be staged and are applied at the next start, before anything loads them. Checksums are checked, the swap is crash-safe, the previous version is kept for one rollback, and an update that fails to load is rolled back once on its own. A free-space guard (2 GiB plus the world's save size) protects your saves.
- **No more rare step stalls.** Kiln.Admin's file bridge no longer touches the disk on the server's tick thread. That caused rare stalls of up to a second while a save forced files to disk.
- **Runtime on Nexus Mods.** The "Kiln runtime (manual install)" file holds the runtime as a folder instead of a zip inside the zip. `kilnctl bundle install kiln-runtime-<version> --dir ...` installs from that folder with the same checks as from the zip. GitHub and frostdev.io keep the zip.

## Modders and tool authors

- **Mod API 0.2.16**, unchanged.
- **Kiln.Admin (KAP/1).** New ops and topics:
  - `metrics` topic;
  - `server_restart` and `server_restart_cancel`;
  - `login_mint` and `login_redeem` (one-time, 60 s);
  - `update_list`, `update_stage`, `update_cancel` and `update_rollback`.
  - `commands_describe` returns form data for every command (argument types, ranges, options, defaults, the owning mod, the permission node and level).
  - `command_run` takes a named `source` with a `level` cap. Send both: a line without them still runs as the full-admin dashboard, for older tools.
- **@kiln/admin-ui.** The launcher's server admin pages are now a package with Tauri and WebSocket transports, ready for Kiln Web Admin. The launcher itself works as before.
- **sigport.** A must-port list (`tools/sigport/must_port.json`) makes a re-port fail, or warn, when it drops a listed game address.

## Not yet seen in a real game

- Flame Altar count in the world list after a save, in a world with Kiln terrain edits inside, outside and at the edge of bases.
- A base over 240 m (altar-size mods) keeping Kiln's edits across saves.
- Saving with another mod hooking the game's save code.
- A restart under kilnctl's real systemd unit, and on a Windows server.
- A staged mod and Kiln update applied on a real server, and on Windows.
- Installing the Nexus runtime folder with kilnctl.exe on Windows.

# Kiln 0.2.0-dev.30.5

A patch for 0.2.0-dev.30.4. The Servers pages are redesigned, and every server action shows what it's doing. Settings is redesigned too, with sections and a search. Mod API 0.2.14 adds custom building tools, which run the game's own terrain tools with Kiln's limits (filtered removal, paid placement, a material picker, build-area checks and the game's own undo), and Fuzen777's requests: controller support for mod UIs, the game's item detail, and outlines through walls. The save editor can add dyes and got a polish pass. Launcher updates take one click. Kiln mode's first start is much faster, and a leftover backup no longer stops EML mods. The Steam Deck's Play page has room for the mod list again. There are fixes for gamepads in Kiln's screens and for cleanup after mod updates.

**Not checked in a real game yet.** Everything passed Kiln's tests, on Windows where it matters. If something looks wrong, tell us on GitHub or Discord with `kiln/logs/launcher.log` or `kiln/logs/kiln.log`.

## Players

- **Servers, redesigned.** Each server now has one page with seven sections across the top (Overview, Console, Players, World, Mods, Backups and Settings), each with its own tabs, and a switcher in the header to move between servers. Overview shows the state in one word, the buttons that fit it, players online, the newest console lines and a "Kiln update available" banner with one-click Update. While a server starts, Overview shows each stage (preparing, Wine where it applies, the server process, loading the world, running), a clock, and about how long the last start took. The old admin pages' links still open the right section.
- **Servers: every action shows what it's doing.** Start, Stop, Restart, Update the game and Install/Update Kiln show their progress the moment you click. You see each step, how long it has taken and the server's newest line, and "Show details" lists every line. When an action fails, the panel says why and offers Try again and the console. Stop works while a start is still waiting for the world. Updating Kiln or the game on a running server is one action: stop, install, start again. The servers list has Start and Stop on each row, with the running step and its time, and a Recent list of what happened to your servers.
- **Settings, redesigned.** Settings is split into six sections (General, Mods & profiles, Game & Kiln, Graphics, Updates & online, and Advanced), each with short groups instead of one long page, and each section's first line says where things stand. A search finds any option by name and jumps to it. Every option from before is still there.
- **The save editor can add dyes.** Dyes such as Shades Of Red or Snowfall were missing from Add item. They're listed now, with their own Dyes filter. Thanks to Wulfhram.
- **The save editor keeps upgrade levels valid.** Upgrading a level-255 item could turn it into level 0 in the save. Levels, upgrades, rarity and gems now stay within what the game allows.
- **The save editor, polished.**
  - **Undo and redo** for your edits, up to 100 steps: the buttons at the top, Ctrl+Z and Ctrl+Shift+Z / Ctrl+Y, or the Deck's controls.
  - **Safer saves and restores.** A restore that fails halfway can no longer leave a half-written save: the current save is backed up first and a verified copy is swapped in. A second save or restore on the same file is refused while one runs. While a save, restore or character load runs, the editor shows it and holds further edits, so a late edit can't be lost silently. "Read again" asks before it throws away unsaved changes.
  - **Backups stay with their save.** Another account's or slot's backups no longer show under your character. Older backups of unknown origin are listed apart ("Older backups (origin unknown)") and can still be restored.
  - **Keyboard.** The whole editor works with the keyboard: skills, moving, swapping and removing items (M to move), and Add item's lists and filters. Durability and water bars work with the keyboard too.
  - **Fixes.** Clearing a number field and typing a new value no longer adds the digits to the old one (120 then 250 became 1250), and a value typed just before Ctrl+S is saved. Duplicating an item and pressing keys quickly could delete the neighbouring stack. Knowledge entries hidden by the filter can't be removed by accident, and removing several asks first. Gems from mods can go into sockets. A read-only save can't be edited. Add item names the real destination slot ("Backpack slot 27").
  - **Small windows and the Steam Deck.** Long character names and missing pictures no longer squeeze Skills, the backpack keeps a full row, item details stack below the inventory on narrow windows, and focus outlines are never cut off.
- **Closing the launcher asks first** when Pack Studio, an editor or the save editor has unsaved changes, or the save editor is writing a save. Before, closing the window dropped them.
- **EML-R's loader is recognised.** Kiln now tells EML-R's game-folder loader (`dbghelp.dll`) apart from ShroudForge's own loader. Before, it could call it ShroudForge's. Kiln doesn't run or switch EML-R mods; EML-R loads them itself.
- **Launcher updates take one click.** After **Update**, the launcher restarts by itself after a 5-second countdown (**Later** stops it). It doesn't restart while you play, while Pack Studio or an editor has unsaved work, or while the save editor writes a save; then it says why it waited. After the restart, the new Kiln goes into the game as soon as the game is closed, with the usual backup. Thanks to HadToRegister and netjunk.
- **The "Updated to" card shows every time.** After an update, the card sometimes showed only its title, or nothing, because the game's status was read before the new Kiln was in place. Thanks to netjunk for the report.
- **Room for the mod list on a Steam Deck.** In desktop mode (or any short window), the OptiScaler note and ShroudForge's own-loader notice could leave Play's mod list with no rows. Both notices now fold to one line with **Hide**, and Kiln remembers that. The list always keeps three rows, and the column scrolls. Thanks to Somamint.
- **Gamepads in Kiln's screens.** A stick let go is recorded as centred, so a Kiln window or an open list no longer keeps scrolling by itself. A second or virtual controller that sits idle no longer overrides the one you use. Thanks to Fuzen777 (#123).
- **Cleanup after a mod update.** Kiln now finishes removing the old copy of a mod even if Windows had a file in it open, and no longer leaves a hidden `.kiln-place-…` folder behind.

### Kiln mode

- **A much faster first start.** The first kiln-mode start, and any start after you change ShroudForge mods, no longer re-reads all of the game's data files (about 50 GB) before writing. Kiln reads samples of them instead, and still checks everything it adds in full. The start bar names each step of the ShroudForge startup pass, so a slow start no longer looks like a hang. On one PC this first start took 2 min 40 s; in Kiln's tests the pass went from 30 s to 4 s.
- **A leftover backup no longer stops EML mods.** A modded backup of the game's data files left by an earlier run (`enshrouded.kfc.bak`) made every EML start fail with "staged content hash mismatch". Kiln now checks the backup before it builds anything. If the backup is provably a leftover and the game's own files are untouched, Kiln makes a fresh backup; otherwise it asks you to verify the game files in Steam. When the last check before writing refuses a start, it now says what to do. Thanks to potter420 (#122).
- **No warning about mods you switched off.** Kiln mode no longer warns that mods are off this start when you switched them off yourself (for example ShroudForge 1.8 mods turned off in the mod list).
- **Writes the game can't confirm.** After a write the game can't confirm, kiln mode reports those writes as unavailable, as ShroudForge does, instead of failing again: asset writes until the game restarts, entity writes until the next world session.
- **Hosted worlds.** On a hosted game, mod overrides in kiln mode follow the world you host, so the right values come back when a mod stops. While a hosted world is loading or closing, kiln-mode mods get "not ready" instead of reading the wrong world.

## Modders

- **Mod API 0.2.14.** Mods built for 0.2.14 need this Kiln; mods for 0.2.13 and earlier keep working.
- **Custom building tools (kiln.tools).** `BuildingToolBlock` with `TerrainBrushBlock` brushes and an optional `ToolMaterialPoolBlock`. Primary and secondary are a declarative `TerrainToolAction` (`Mode` = `TerrainToolMode.Remove` | `Add`, a per-tool `RemoveMaterials` list of terrain cells, `TerrainOnly`). Tools run the game's own terraform, so the game's own payment (backpack, then connected magic chests), its own mining yields, its normal undo with exact refunds and its building-area permissions all apply. Kiln only narrows what a tool may remove or place: buildings and props are never touched, and a stroke crossing the Flame Altar edge is refused as a whole.
- Pool entries (`ToolMaterialPoolEntry`: item, terrain material, voxels per item) must be materials of the game's terrain pool. Kiln keeps the pool to itself and doesn't add rows to the game's material pools, so vanilla tools and magic-chest counts are unchanged.
- While a mod's tool is held, the game's material picker shows only that tool's pool and the brush list shows the tool's own brushes. Vanilla tools are unaffected.
- `BlockIdentity.Legacy(Guid | uint)` on items, recipes, tools, brushes and knowledge entries keeps the identity an item had in an older mod, so saves made with it keep their items.
- `RecipeBlock.MenuGroup` puts a recipe into an existing station tab (`CraftingGroups.<Station>.<Tab>`, for example `CraftingGroups.Carpenter.Essentials`, or a `CraftingGroupRef`). `RecipeBlock.TrackCrafted` marks a recipe as tracked when crafted.
- `KnowledgeBlock` (`Trigger` = `Pickup` | `Craft`) tracks picking up an item or crafting a recipe, like the game's own knowledge entries.
- Native: new table `kiln.tools` v1 (64 bytes: status, define/remove family, material snapshot, presentation status; `register_action` reserved, returning unavailable). Capabilities: tool actions, terrain carve, payment, history, picker and brush rows, each with its refusal reason.
- Mods with building tools can be loaded, unloaded and baked in the TestKit and SDK, so their items exist on a player's first start.
- Not yet: `ToolMaterials.TrySnapshot` (per-player stock counts) reports unavailable in this release. Tool actions are declarative only: there is no mod callback.
- Controller support for mod UIs (#119): bind actions to controller buttons and combinations (`Pad:A`, `Pad:LB+A`, ...), read the slot the game's controller selection is on (`Ui.Inventory.Selected`), and handle controller presses on that slot (`SlotClickOptions.Pad`). TestKit: `HarnessUiInventory.Select`, `PressPad`. Thanks Fuzen777.
- Visible slots and clicks carry rarity and level (#121), and player and open-container slots give the proven server item entity (`VisibleSlot.ServerEntity`); new `kiln.ui.slots` v1 table. The released 0.2.13 slot records are unchanged for existing mods. Thanks Fuzen777.
- Captured item detail (#120): the text and computed numbers of the game's own item panel after the player inspected the item (`Ui.Values.ItemDetail`, capability `ui.item_detail`, client only), with an explained miss instead of invented stats. Thanks Fuzen777.
- `OutlineOptions.ThroughWalls` (#111): an outlined entity can also be seen through walls as a screen-space silhouette that respects outline suppression, priority and lifetime (capability `ui.world_outline.through_walls`; kiln.render v3). Thanks Fuzen777.
- ABI note: outline status gains an optional position tail (24 to 56 bytes, alignment 4 to 8); existing 24-byte callers, including 4-byte-aligned ones, are supported unchanged.

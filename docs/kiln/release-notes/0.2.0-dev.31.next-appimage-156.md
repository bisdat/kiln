# Kiln 0.2.0-dev.31.next: Kiln Launcher once in the app menu under Gear Lever (GitHub #156)

## Players and server admins

- **Kiln Launcher shows up once in the app menu when Gear Lever installed it.** Gear Lever, AppImageLauncher and
  appimaged add their own app menu entry for an AppImage. The launcher added its own entry as well, so the menu and
  Gear Lever's list showed "Kiln Launcher" twice, and removing one in Gear Lever uninstalled the whole app. On
  Bazzite, Silverblue and Kinoite the two entries even looked different: one started the AppImage from `/home/...`,
  the other from `/var/home/...`, and those are the same folder. Now, when such a tool has already added Kiln, the
  launcher adds no entry of its own and removes the one it added before. Entries made by Gear Lever or by you are
  never touched. Nexus Mods "Mod Manager Download" links and `kiln://` links work as before, and Kiln's icon stays.
  In Settings, Appearance, "Kiln Launcher in the app menu" now says "Gear Lever (or another AppImage integrator)
  already added Kiln to the app menu" instead of offering a second entry. If you turned that switch off to work
  around the duplicate, you can leave it off. The .deb, the .rpm, the Steam Deck and an AppImage you run without
  such a tool work as before. Thanks to Dark-Thoughts for the report and the two entries' files (kiln#156).

## Modders

- No mod API change: mod API 0.2.26.
- **How the launcher tells** (`launcher/src-tauri/src/desktop.rs`, `Integration::find`). It writes no
  `kiln-launcher.desktop` and removes its own (the one with `X-Kiln-Desktop-Entry=1`) when either holds:
  - `DESKTOPINTEGRATION` is set in its environment (not empty, `0`, `false` or `no`), the AppImage convention these
    tools follow;
  - another entry the menu shows has an `Exec` argument or `TryExec` that is the same file as `$APPIMAGE` once both
    paths are resolved. "Shows" means `Type=Application`, not `NoDisplay` or `Hidden`, and the first file with its
    desktop id across `$XDG_DATA_HOME/applications`, then each `$XDG_DATA_DIRS/applications`, subfolders included.
    Quotes, the spec's escapes and field codes are read.
- Settings: `DesktopInfo.integrator` (`app_info`, `app_desktop_set`) holds `DESKTOPINTEGRATION=<value>` or the other
  entry's file. While it is set, the switch is off and not offered.
- The icons in `$XDG_DATA_HOME/icons/hicolor` stay up to date: the NoDisplay nxm and `kiln://` handler entries name
  `Icon=kiln-launcher`. Those handler entries are written by their own code and this change leaves them alone.

## Not yet seen in a real game

- Not tried under a real Gear Lever, AppImageLauncher or appimaged install, or on Bazzite. Tests cover it with
  temporary XDG folders: `DESKTOPINTEGRATION`, a Gear Lever entry reached through a linked `/home`, another AppImage's
  entry, someone else's file kept, and the Settings line.

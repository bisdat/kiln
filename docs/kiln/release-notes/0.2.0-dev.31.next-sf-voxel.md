# Kiln 0.2.0-dev.31.next: ShroudForge voxel writes

## Players and server admins

- **ShroudForge mods can change the world's blocks again.** Under Kiln every ShroudForge voxel write (`runtime.world.voxel.write`) was refused with "voxel write was rejected before changing the world", so mods like Altar Cleanup found the cells and changed none. ShroudForge's own writer reads the game's code down to the block writer and gives up on the first hook it meets, and Kiln and its mods always hook that code. Kiln now writes ShroudForge's cells itself on the server world's thread, through the same engine writer. The mod keeps its undo, and the cells are saved where the game saves them (inside base build zones), as without Kiln. When Kiln still refuses a write, kiln.log says why on a "ShroudForge voxel write ..." line. Thanks to netjunk for the report and the logs.
- **A ShroudForge mod with one failed change no longer shows as not loaded.** When a mod reports that its last change did not apply (`write-failed`) and ShroudForge still runs it, Kiln's in-game mod menu shows it loaded, with the report as a warning. Before, the whole mod showed red as if it had failed to load. Red is now kept for mods that did not load or were stopped (reported by netjunk, Altar Cleanup).

## Modders

- ShroudForge fork `kiln-dev31-voxel-write` (`6cf01443`, on top of `a9dc2ad2`): the host table (`abi/runtime_host.h`) gets two optional members, `voxel_write_ready` and `voxel_write`. With both, `runtime.world.voxel.write` and `runtime.has("runtime.world.voxel.write")` go to the host, which keeps ShroudForge's outcome codes (0 written, 1 refused before any change, 2 put back, 3 uncertain) and limits (65,536 cells a call). A host without them, and ShroudForge's own loader, keep upstream's writer.
- Like ShroudForge's own writer, Kiln refuses a box outside the voxel grid (a coordinate below 0, x or z past the grid), a write that would reach another server world than the one the mod asked in, and, after a write with an uncertain outcome, every further voxel write in that world until it is loaded again. kiln.log names each reason.
- kiln.build: `KILN_BUILD_F_GAME_SAVE` (native, bit 6) writes under the game's own save rule: no Kiln save region, and no need of the save-region hook. It is refused with `KILN_BUILD_F_TRANSIENT`. Not in `BuildFlags`, and the mod API is unchanged.
- Kiln's in-game mod menu shows a ShroudForge mod's `write-failed` effect as loaded with a warning while ShroudForge lists the mod active. The `error` effect (a native DLL that failed to load) and ShroudForge's per-mod errors stay failed.

## Not yet seen in a real game

- Altar Cleanup's cleanup and undo in a hosted world on a real client (client 26430625).
- The mod menu's warning colour for a ShroudForge mod that reported `write-failed`.

# Kiln 0.2.0-dev.29.2

A patch for 0.2.0-dev.29.1: switched-off XHL mods stay off, the first open of Kiln's mods page no longer stalls the game on a hard drive, and the launcher's text no longer suggests copying a loader over Kiln. The SDK stays at 0.2.0-dev.29. Everything else is as in 0.2.0-dev.29.1.

## Fixed

- **Opening Kiln's mods page the first time no longer stalls the game on a hard drive.** To draw the page in the game's own font, Kiln read the font out of the game's data, and it read about 2 GB of that data to get two small files: on a hard drive that took about 25 seconds, and the game could drop out of borderless fullscreen for a moment (the taskbar showed, the picture shifted, a busy cursor). Kiln now reads only the font itself. `kiln.log` says how long it took ("the game's UI font loaded (… read in … ms)").
- **The launcher no longer tells you to copy a loader named `dinput8.dll` into the game folder.** That file is Kiln's own, so copying another loader there (Ultimate ASI Loader, for example) replaced Kiln. The Library now says not to copy it over Kiln's `dinput8.dll` and names the supported way: another name listed in `dinput8-chain.ini` (for Ultimate ASI Loader, `xinput9_1_0.dll`).
- **Switching an XHL mod off in Kiln stops it.** An XHL mod (Vein Mining, Area Harvest and the rest of the XHL family) whose `native-plugin.ini` you had changed, for its settings or with XHL-Core's own switch, kept its folder in the game's `mods` folder when you switched it off in Kiln, and XHL-Core went on loading it from there. That file now counts as the mod's settings: the folder goes, the file waits in `kiln/state/placed-settings` and comes back when you switch the mod on again. The same goes for an XHL mod with ShroudForge settings you changed. A new version of the mod whose DLL has another name starts with its own `native-plugin.ini`, and Kiln says where yours waits.
- **Kiln says when it cannot stop an XHL mod.** An XHL mod's folder you put in the game yourself stays when you switch the mod off in Kiln (Kiln never removes a folder it did not place), and XHL-Core still loads it: the launcher now says so, and how to stop it. A ShroudForge mod that is an XHL-Core plugin too (Building Tools for ShroudForge) is switched off in ShroudForge, but XHL-Core still loads it where the game has XHL-Core: the launcher says that too.
- **Settings that come back are named.** When a mod's settings come back from `kiln/state/placed-settings` (you switched it on again, or removed it from the Library and added it again), the launcher now says so and where they came from.
- **No warning about a switched-off mod's folder.** `kiln.log` no longer says "folder ... is missing; skipped" for a mod that is off in your profile: Kiln removes such a mod's folder from the game folder on purpose.

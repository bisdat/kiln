# Kiln 0.2.0-dev.31.10

## Players

- **The Spell slot no longer empties after a fast switch.** With a mod that swaps spells or arrows in the HUD list (such as Grimoire), switching as fast as the game allows right after a swap could empty the Spell slot. Kiln now hands that pick to the mod instead of the game (#145). Thanks Fuzen777.

## Modders

- **HUD spell and arrow lists (#145).** The game got a pick of the spell a mod's swap had just moved out of the backpack while the list still showed it, and emptied the slot without raising `Picked`. That pick now reaches the mod as `Picked`, both before the game rebuilds its rows and in the frame or two after, before Kiln republishes the mod's rows. With `"log_level": "debug"` in `kiln.json`, Kiln logs every pick of a mod's row that it hands to the game (`ui.ammo: a pick of ... went to the game: ...`, at most 8 lines a second). No API change (mod API stays 0.2.19).
- **Not covered:** `Ui.AmmoList` in Append mode (including `PlayerStorage.Client.ProvideAmmo`) leaves a mod's row out while the game lists that item with stock, so a just-swapped-out item is not a mod row in that window.

## Not yet seen in a real game

- Which pick emptied the reporter's slot, how long the window lasts in the game, and the cost of the backpack reads when the rows are bound. The native host tests cover the race in Replace and Append mode; the static facts were read from the game's code.

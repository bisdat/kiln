# Kiln 0.2.0-dev.30

This release brings **Crucible**, modpacks for Enshrouded on frostdev.io: share your mods with a friend as a link or an
eight-letter code, install a pack in two clicks as a profile of its own, and get its updates without losing your own
changes. Pack Studio in the launcher is for people who make packs. For mod authors there is an equipment API (an
item's rarity, its values, lines in the game's own tooltips, rarity upgrades and rolls), hooks into the game's own
inventory screens (marks and clicks on slots, panels beside the backpack and chests), client hooks as an advanced tier,
and Kiln tasks that can run in the main menu. Kiln tasks stay experimental. Kiln's own save writing now runs on Kiln's
task pool. The mod API is 0.2.12.

Also in this release: Kiln's Windows files are signed, which should stop most antivirus false positives. Joining a
server with mod buffs works again: update Kiln on the server and on every player's game. A first start no longer
freezes now and then under Wine or Proton while Kiln sets up its hooks, and "Play once" works again for a profile with
Enshrouded ModLoader mods that run on ShroudForge. Launcher fixes from player reports (thanks to HadToRegister and
Oryx593).

ShroudForge and EML mods on Kiln's own engine are not in this release. They come in a dev.30.x patch in the next few
days. ShroudForge's own runtime (1.7.9) stays available as before.

Nothing ships held: every capability is on. **Not all of it is checked in a real game yet.** This release passed
Kiln's tests, and Crucible was tried end to end against a local copy of the service. The sections "Seen in a real
game" and "On, not yet confirmed in a real game" below say which is which. If something looks or works wrong, tell us
on GitHub or Discord with `kiln/logs/kiln.log`.

## Players

- **Kiln's Windows files are signed.** The launcher, its installer and Kiln's files for Windows now carry a digital
  signature (Authenticode, publisher Frostdev). That should stop most antivirus false positives: Kaspersky and ESET
  flagged `kiln-greeneye.dll` before. If your antivirus still flags a Kiln file, tell us which one and which antivirus.
- **Joining a server with mod buffs works again.** On a server whose mods add buffs (a StatusBlock, for example), or
  which still keeps the placeholders of a removed mod's buffs, every Kiln player waited 25 seconds at the join and was
  then refused with "Waiting for this game's content and added-buff capacity check". This was on 0.2.0-dev.29 to
  0.2.0-dev.29.23. A player who got in could still be refused with "kiln.abilities did not register the programs (4)"
  when such a mod loaded. Your game now answers the server's check right away, and the check is finished once your
  world is running. **Update Kiln on the server and on every player's game.** A dev.30 game is still refused by a
  29.22 or 29.23 server with mod buffs until the server updates. Players on an older Kiln can play on a dev.30
  server, and nothing refuses them for the programs error any more. Thanks to Roger de R'lyeh for the report.
  Details: [sync.md](../sync.md).
- **Crucible: share your mods as a link.** On Play, **Share to Crucible** turns your profile into a pack: every mod,
  your choice of settings and the load order. The first share asks you to sign in with Discord; your friends don't need
  to. You get a link and a code like `H7QK-3MZP` to paste to them. Only the files Crucible doesn't have yet are
  uploaded, so a pack of popular mods goes up quickly, and you can close the window while it uploads. When you change
  the profile later, a "Pack changed" pill offers **Update link**, and your friends get the new version as an update.
  **Save as file instead** makes a `.kilnpack` file you can send any other way. A link-only pack that nobody uses for
  a year goes away; public packs stay.
- **Crucible: install a pack from a code or a link.** Click a pack link, or use **Got a code?** on Play. Kiln shows the
  pack first: who made it, how much it downloads (mods already in your Library are not downloaded again), whether it
  fits your game build and your Kiln, and a warning that it contains mods, including code, from other people. Install
  makes a new profile for the pack and loads it; your other profiles stay as they are, and **Back to** puts your
  previous profile back. Your saves are backed up first. A game client downloads only what a player needs, not the
  pack's server-only mods. "Always trust packs from <creator>" saves the extra click for people you know.
- **Pack updates keep your changes.** When the creator publishes a new version, a banner says what changed. The update
  keeps the settings you changed, the mods you added and the switches you flipped, and takes the creator's new values
  for everything you left alone. Where you and the creator changed the same setting, Kiln asks which one to keep before
  it changes anything. A settings file the creator renamed takes your values with it. Your saves are backed up first,
  and **Undo last update** in Settings > Profiles goes back one version. An update either completes or leaves the pack
  as it was.
- **Your own changes to a pack's data.** Edits you make to a pack's game data (an item's stack size, a recipe) go into
  a layer of your own that loads after the pack, so they still win after an update. When an update changes the same
  value, Kiln shows both and offers **Drop my change**. Players who join your world need nothing for it.
- **Packs are checked.** Crucible checks every version of every pack when it is uploaded: the file's structure and
  sizes, known-bad files, the mods' code, and data that two mods set differently. The launcher runs the same checks on
  a `.kilnpack` file you drop on it or open: problems that would break the install stop it (in red), things worth a
  look are shown in yellow, and "Checks: passed" otherwise. Checks are not a review: read the pack's comments, and
  report a pack that does harm.
- **Crucible on frostdev.io.** <https://frostdev.io/kiln/crucible> lists public packs, with search and filters (tags,
  game build, for players or servers, number of mods) and sorting by top, new, updated and installs. Each pack has a
  page with its versions, what changed, the mods and who made them, comments, upvotes and a Report button. Sign in with
  Discord to comment, upvote or report; "Sign out and forget me" removes your account data. A pack link pasted into
  Discord shows a card with the pack's name and cover.
- **From the website to the game in one go.** A pack page's **Get Kiln** button leads to the download with the pack's
  code in the file's name. The first time the launcher starts it opens that pack's preview ("Kiln is ready. Here is
  <pack>, the pack you came for."). Nothing installs until you click.
- **Crucible on Discord.** The Kiln app's `/modpack open <code>`, `/modpack find <words>` and `/modpack share` (your
  own packs) post a pack with an **Install in Kiln** button.
- **Show my Crucible pack on my Discord profile.** With Rich Presence on, a second switch (off by default) shows the
  Crucible pack you are playing, "Ember run (12 mods)", and a **Get this modpack** button that opens its page. Packs
  made or opened from a file on your PC are never named, and still no server, world or character name is shown.
- **Count my installs (anonymous) is on by default.** When it is on, Crucible counts one install per pack and day;
  nothing about you is sent. To turn it off, use the switch **Count my installs (anonymous)** in Settings > Launcher.
- **Steam Deck.** Crucible works in the Deck layout: enter a code, install, update, and share with a code your friends
  can scan with a phone. Pack Studio is desktop only.
- **Mods can mark and use the slots in the game's own inventory screens.** A mod can draw a mark on an item's slot (a
  border, a fill or a corner) that follows the item wherever the game draws it, react to a click with a key held
  (Ctrl+click, for example) on the item it means, and dock a small panel beside the backpack or a chest's screen with
  buttons of its own, such as a "Salvage marked" button next to a chest. Clicks count only on screens with a mouse
  pointer, never in the play view, and a click a mod does not ask for goes to the game as before.
- **Mods can show more in the game's item tooltips.** Mods with the new equipment API can add lines to the game's own
  item detail view, in the game's colours and wrapped like the game's text, and show their changed numbers in its stats
  block. They are on for every player.
- **Gear with rarity of its own.** With mods that use it, items you craft or loot can come out at a rolled rarity, an
  upgrade station can raise an item's rarity for a price, and single items can be stronger, tougher or longer lasting
  than others of their type, and keep it in your save. The game itself draws the rarity, its colour and the extra
  enhancement slot.
- **Kiln's own save writing runs on Kiln's task pool**, not on a thread of its own. Saves are written in the same order
  as before, and everything still queued is written whole when you quit. If the pool cannot run it, Kiln writes the
  old way and says so once in `kiln/logs/kiln.log`.
- **Linux: the launcher can switch to X11 when it is slow on Wayland.** On Wayland, if the launcher can't use your GPU
  and feels laggy, it now restarts once through X11 (XWayland), which often fixes it, and remembers the choice for
  next time. Your own `GDK_BACKEND` setting always wins, and you can turn this off in Settings > Appearance ("Switch
  to X11 when drawing is slow on Wayland"). Thanks to Oryx593 for the report.

## Mod and pack makers

- **The mod API is 0.2.12.** Everything new is additive: no public member of 0.2.0-dev.29 was removed or changed.
- **Pack Studio** (the launcher's Studio page) makes Crucible packs. Start from one of your profiles or an empty pack.
  **Mods**: required or optional (on or off by default), and whether each runs for players, on servers or both.
  **Settings**: "Capture from my current settings" offers the keys that differ from each mod's defaults; hotkeys are
  marked personal and left out unless you tick them, and anything that looks like a password, token or webhook can
  never be chosen. **Data**: editors for the pack's own data layer (items, recipes, loot, drops, new items, raw JSON)
  with the game's icons and Kiln's lint after every change. **Load order**: the order Kiln will use, the pack layer
  last, and every field two mods set differently, with **Set in the pack** to decide it. **Test this pack** installs a
  test copy and shows what the game logged at its start; use a new world for it. **Credits**: prefilled from the
  pack's analysis, confirmed by you. **Publish**: link only or public, and **Put on a server** for a published
  version. A publish that stops midway carries on with the same version the next time. Public packs need a credit
  (author and https link) for every mod, a short summary, and a Discord account in the Kiln Discord that is at least
  three days old; until then the pack stays link-only and the Studio says what is missing (**Make public** asks again
  without a new version). Details: [launcher/pack-studio.md](../launcher/pack-studio.md).
- **`kilnctl pack`.** `pack init`, `add`, `capture-settings`, `lint`, `credits`, `build` and `publish` do the
  Studio's work from a terminal on a pack folder; `pack install`, `update` (with `--resolve PATH#KEY=pack|mine`),
  `diff`, `undo`, `uninstall`, `list` and `server` handle installed packs, and `pack check` runs Crucible's checks
  on a `.kilnpack`. `install`, `update` and `server` need `--yes`: a pack runs code from other people. Details:
  [launcher/crucible.md](../launcher/crucible.md), [kilnctl.md](../kilnctl.md).
- **The pack format** (`kiln-modpack.json` format 2 in a `.kilnpack`) is documented with its schema
  (`schema/kiln-modpack.schema.json`, `schema/kiln-pack-instance.schema.json`). A build from the same profile gives
  the same bytes. Server modpacks (format 1) stay as they are, and each reader names the other's files.
- **New lint warning KL701 (data-conflict):** two mods linted together (`--profile`, or a pack's mods) set one field of
  one game entry to different values; the later mod wins. `kilnctl pack check` lists every such field of a pack.
  Details: [modding/lint.md](../modding/lint.md#kl701-data-conflict).
- **An item's rarity, enhancements and level.** `Items.GearOf`, `RarityOf`, `SetRarity`, `SetEnhancements` and
  `SetLevel` read and write them in place on the server: the same item, with its item data, affixes and gem kept. The
  game then draws the rarity, the "LEVEL x/y" line and the damage itself. `GearRarityChangedEvent` and
  `GearEnhancedEvent` (also for a player's own workbench unlock). No tier above Legendary. Details:
  [services/items.md](../services/items.md).
- **Values of a single item.** `Items.SetPower`, `SetArmor` (0.01 to 100 times), `SetDurabilityMax` and `SetLevel` with
  `AnyLevel` make one item stronger, tougher or longer lasting than others of its type, wherever it goes; Kiln keeps
  the values with the item and writes them again after each load. `Items.ValuesOf` reads them.
- **Gear values without code.** A data pack's `gear` section (and `Content.Gear` in C#) sets an item type's power,
  damage kinds, armour, speed, levels, rarity, perk slots, socket and more in the numbers the game's tooltip shows;
  Kiln solves the game's formulas for you. `gearRules` sets the game's balancing values for gear (durability per
  rarity, socket chances, the durability curve, the enhancement unlock cost) as boot values. A player without Kiln sees
  the game's own numbers in the tooltip. Sample: `mods/samples/GearValues`. Details:
  [services/content.md](../services/content.md#gear-values).
- **Rarity rolls when an item is made.** `RarityRollBlock` (`rarityRolls` in `blocks/*.json`) names item types and
  five weights, and the server rolls the rarity whenever the game makes one of them: a craft, random loot, a drop. One
  item type then covers Common to Legendary. Lint warns when a rolled craft's recipe tooltip would show another rarity
  than the craft gives. Details: [modding/item-blocks.md](../modding/item-blocks.md#rarity-at-creation-rarityrollblock).
- **Rarity upgrades and upgrade stations.** `Items.UpgradeRarity` raises an item's rarity by one step of a rule (cost,
  chance, what a failure costs, a price that grows with the level, a chest that pays), all or nothing in one server
  step; the item gets its next enhancement slot, which the player unlocks at the workbench as usual.
  `RarityUpgradeBlock` (`rarityUpgrades`) is the same as data. `InteractBlock.Upgrade` makes a placed thing an upgrade
  station: the held item for every player, or a Kiln window listing the player's gear for Kiln players
  (`UpgradeStation.Offer` from code). `GearUpgradingEvent` can cancel or reprice an upgrade. Sample:
  `mods/samples/RarityAnvil`. Details: [modding/world-blocks.md](../modding/world-blocks.md#upgrade-stations).
- **Lines and numbers in the game's own item tooltip.** `Ui.Tooltip.AddLines` draws lines after the stats or at the end
  of the game's item detail view, wrapped and in the game's colours (rarity colours, `Positive`, `Negative`,
  `Muted`, optionally smaller); `Ui.Tooltip.AddValues` scales the numbers its stats block draws, in this player's game
  only. Where the game's view cannot take the lines they go to Kiln's Item details window instead. Details:
  [ui.md](../ui.md#lines-and-numbers-inside-the-games-item-detail-view-uitooltip-equipment-wave).
- **The game's inventory slots: `Ui.Inventory`.** `OnClick` gives clicks on the game's slots with an exact button and
  modifiers and the item's entity (the server's own id, so your server half can check it); by default the game never
  sees the press. `Mark`, `MarkWhen` and `Hovered` draw marks over slots and say which slot is under the cursor.
  `AddPanel` docks a Kiln panel beside the backpack and chest screens; `Screen`, `ScreenChanged` and
  `GameScreen.Target` say which is open, with the chest's entity. A click is a wish, never authority: check it on the
  server. Native plugins: `kiln.ui.inventory` (v2) and kiln.ui's `subscribe_pointer_press`. Kiln.TestKit fakes it
  offline. Sample: `mods/samples/SlotMarks` (marks with a server half that checks ownership, and a "Count this chest"
  panel). Details: [ui.md](../ui.md#the-games-inventory-slots-0200-dev30).
- **Client hooks for mods (advanced tier).** A mod with `"advanced": true` can hook the game client's own functions,
  with typed hooks, `Hooks.Detour` and `Hooks.Mid`, on functions Kiln names or on functions it describes in its own
  `sigdb/client.json`. Kiln installs them only on a game build it has measured, at a safe point, after checking every
  other thread, and refuses a pattern that no longer fits after a game update instead of guessing. A Kiln API is still
  the first choice: hooks of your own may stop working after a game update until you update the mod. Sample:
  `mods/samples/ClientHookSample`. Details: [modding/client-hooks.md](../modding/client-hooks.md).
- **Kiln tasks stay [Experimental] in dev.30.** `WorldConcurrent` and its types, and Kiln.TestKit's
  `FakeWorld.BusyReads` and `BusyWrites`, still need `<NoWarn>$(NoWarn);KILNX003</NoWarn>` in your project, as in
  0.2.0-dev.29. They were checked on a dedicated server (a new lab: 73 checks, under load, reloads and stops with
  tasks in flight), on native Windows 11, and in a real game on a hosting client. A real game on a
  dedicated server with a joined player is still to come. They still work only on the two game builds Kiln has exact
  profiles for (server 26430253, client 26430625). Details: [modding/tasks.md](../modding/tasks.md).
- **Kiln tasks can hop to the main menu (GitHub #83).** `await ctx.ToTick(WorldKind.Menu)`,
  `ctx.OnTick(WorldKind.Menu, ...)` and `ctx.PostToTick(WorldKind.Menu, ...)` run on the game's UI frame while no
  world runs (the title screen and between worlds), about 30 times a second with a small budget of their own. Only
  any-thread and main-thread UI APIs work there; world APIs throw an exception that says it is a menu hop. Menu work
  still waiting when you host or join a world is cancelled. Kiln.TestKit has `kiln.MenuFrame()`. Details:
  [modding/tasks.md](../modding/tasks.md#hops-in-the-main-menu).
- Kiln's analyzers know the new `rarityRolls` and `rarityUpgrades` sections of a mod's data.

## Server owners

- **Put a pack on a server.** Pack Studio's **Put on a server** (for a published version) and `kilnctl pack server`
  put a pack's server mods, its server settings and its game settings on one of your servers (refused while it runs)
  and build the player modpack for it, so joining players get the offer as with any server modpack. A pack carries only
  game settings: a server's name, ports, passwords, user groups and bans never travel in a pack.
- **Equipment mods run their rules on the server.** Rarity writes, rolls, upgrades and the values of single items are
  decided by the server. A player without Kiln sees the game's own numbers in tooltips and can take an upgrade a mod
  offers on one of the game's own objects (`UpgradeStation.Offer`); a mod's own station, the gear window and modded
  tooltip lines need Kiln. `gearRules` are boot values: they
  apply from a start.
- If a server with a task mod ever stops stepping for many seconds, send `kiln/logs/kiln.log` and
  `kiln/logs/tick-stats.jsonl` (seen once in a test lab, not again in six runs).
- **Update Kiln on the server for the join fix.** A 0.2.0-dev.29 to 0.2.0-dev.29.23 server with mod buffs refuses
  every Kiln player after 25 seconds, and players with dev.30 too. A dev.30 server lets in players on an older Kiln as
  before: it checks them once their world runs, and it no longer refuses them for "kiln.abilities did not register
  the programs (4)". A player who does not answer the check within 25 seconds is refused with "Your game did not
  answer this server's content and added-buff check in time".
- **Linux servers under Wine or Proton** get the hook fix below: a start that froze for good while Kiln set up its
  hooks now goes on.

## Fixed

- **A first start no longer freezes now and then under Wine or Proton.** On Linux and the Steam Deck, the game, or a
  server on Linux, could freeze for good while Kiln set up its hooks, if the game was creating a thread at that
  moment. Kiln now skips a thread that has not started running yet, since it cannot be in the middle of game code.
  On Windows nothing changes.
- **"Play once" works with Enshrouded ModLoader mods that run on ShroudForge.** When a profile had such a mod, Play
  once always refused with "ShroudForge mods use a fixed game folder", even for the profile you were already using.
  Kiln counted its own compatibility copy of the mod as a change to ShroudForge's folder. It no longer does. A real
  change in that folder is still refused. Play once is now also refused if it needs ShroudForge's runtime package
  while your active profile has it off, so the game no longer starts without it.
- **Add Mod is no longer undone now and then.** The launcher's profile watcher could rewrite Kiln's settings file at
  the same moment, and the add failed with "Unable to find file". Thanks to HadToRegister for the report.
- **Saving a support report could silently write nothing.** It now always writes the file, and `launcher.log` says
  where and how big, or why not. Thanks to HadToRegister for the report.
- **The launcher no longer slows down a PC with hard disks.** It no longer checks the game folder while it is
  minimized or in the background. While you use it, the checks run every 30 seconds, and they never write anything
  when nothing changed. On a hard disk this was slowing down Windows itself. Thanks to HadToRegister for the report.
- **A mod file that is still downloading or being scanned by your antivirus is waited for**, and a half-finished
  browser download (`.crdownload`, `.part`) is refused with a clear message. Thanks to HadToRegister for the report.
- Kiln's docs said a stack overflow inside a native plugin's task is contained on native Windows. It is not, as under
  Wine: the task stays running and its worker is lost, while other mods keep running. Details:
  [services/tasks.md](../services/tasks.md#faults-the-pool-cannot-contain).

## Seen in a real game

Checked by us in a real game (a hosted world, Linux with Proton, game client 26430625) on 2026-11-20:

- **Kiln tasks in a world you host:** 100 tasks off the game's main thread and back, hops to the server and client
  steps, and a task reading the client world, in two worlds one after the other (a task left running in the first
  world stays behind).
- **Kiln tasks in the main menu (GitHub #83):** work still waiting in the menu is cancelled when the world starts.
- **Client hooks:** a mod's own client hook (ClientHookSample) installs and runs in the game.
- **`Ui.Inventory`:** Ctrl+click on a weapon in the backpack reaches the mod with the item and its entity, and the
  game does not pick it up, while a plain click works as before; clicks in a chest reach the mod with the chest's
  item, and a click the mod only watches still reaches the game; a panel beside the backpack and the chest, shown
  only on chest screens and hidden when the chest closes; the chest screen names the chest's entity; marks drawn
  exactly on the backpack's, the chest's and the action bar's slots that hold items, none on empty ones (at 1920x1080).
- **The equipment API:** gear values from a data pack in the game's own tooltip, mod lines placed after the stats
  and at the end of the tooltip, an item's level and values kept after quitting and hosting the world again, and a
  mod scaling the stats block's numbers (Damage doubled, then back).
- **Kiln's save writing on the task pool:** the save when you quit to the menu wrote the mods' data, and hosting the
  world again read it back exactly.

## On, not yet confirmed in a real game

- **Crucible in a real game:** installing a pack and playing it, a player-layer change surviving an update, **Test
  this pack**, **Put on a server** and a join to that server, and the Windows installer that opens the pack you came
  for (`setup.crucible-<CODE>.exe`). The service, the website and the launcher were tested end to end against a local
  Crucible.
- **The rest of the equipment API:** power and armour of single items in hits, tooltip lines when there are many
  (scrolling), wrapping in English and German, colours, the upgrade stations, the workbench
  unlock after an upgrade, durability after an upgrade, rolled crafts, and a rarity change seen live.
- **`Ui.Inventory`:** marks at a second resolution or UI scale, and the slot under the cursor (`Hovered`).
- **Kiln tasks** on a dedicated server with a joined player, and in a real game on native Windows.
- **The join fix** passed Kiln's tests and two lab runs on a server with a mod that adds two StatusBlocks (one with
  only the placeholders of its buffs left), where Kiln's network test clients were held, let in and refused as they
  should be (8 of 8 checks each). Nobody has joined a server with it from the real game yet.
- **The Wine and Proton freeze fix** ran 300 times under Wine and 180 times on Windows without a freeze; it has not
  been seen in a real game start yet.

## Known limits

- **Crucible**: an engine mod whose settings live in its own folder (not the profile's config folder) cannot carry
  settings in a pack yet. A pack's optional mods are downloaded even when off, so switching one on later needs no
  download. A test instance shares the game's saves like any profile: use a new world. The pack editors write plain
  JSON, so comments in a data file the editor saves are lost (Raw JSON keeps text as typed). Browsing, comments and
  upvotes are on the website, not in the launcher.
- **Inventory slots**: no gamepad focus yet (only the mouse), no button drawn by the game's chest screen itself (a Kiln
  panel beside it instead), and when two mods mark one item only one mark shows.
- **Tooltips**: the enhancement rows of the stats block are not scaled, nor is the damage-type number beside Damage
  ("Cutting 40"); a scaled Damage shows in the game's own better/worse style ("40 > 80"). There is no rarity above
  Legendary.
  Scaled numbers are a picture on this player's game: the server's numbers do not change.
- **Equipment**: a player's own workbench unlock is seen by a read of the players' items, one player per step, and only
  while a mod listens; items in chests are not read. What a player is told at an upgrade station is English.
- **Kiln tasks**: a stack overflow in a native plugin's task is not contained (above), on native Windows as under Wine.
- **Client hooks** run only on game builds Kiln has measured; a hook of your own needs an update of your mod after a
  game update.

# Kiln 0.2.0-dev.30

## Fixed

- **Mods that only work from the game folder now get there.** A plugin loader such as "Autoloot and coop loot sharing" (`powrprof.dll` with its `plugins` folder) did nothing under Kiln, because Kiln loaded it from its Library folder, where it found no plugins. When such a mod is switched on, Kiln now copies its files into the game folder, and the game loads it itself. When you switch it off or remove it, Kiln takes out the files it put there. Settings you changed stay, and so does a `powrprof.dll` Kiln did not put there (Shrouded Engine Tweaks' loader, or your own copy): then Kiln says that it left the mod out. You don't need to add the mod again. Under Proton the game needs a DLL override for that file, and the launcher's notes name it.
- **Ultimate ASI Loader and `.asi` mods work next to Kiln.** Add Ultimate ASI Loader's download (its `dinput8.dll`) and an `.asi` mod such as Smart Workshop (its `Scripts` folder) to the Library like any other mod. Kiln puts Ultimate ASI Loader next to the game as `xinput9_1_0.dll`, so Kiln's own `dinput8.dll` stays, and the plugins go where the loader looks for them. Kiln takes them out again when you switch them off. An `.asi` mod alone uses the Ultimate ASI Loader Kiln's installer already set up, if there is one. Don't copy Ultimate ASI Loader's `dinput8.dll` into the game folder yourself: that would replace Kiln. On Linux (Proton) the launcher asks for `xinput9_1_0` in the Steam launch option.
- **Shroudlink singleplayer: Kiln names the file that stops your Shroudlink mods.** If a `shroudlink_core.dll` from an earlier hand installation is still in the game folder, Shroudlink's client addon starts that core, and your profile's Shroudlink mods (Expeditions, Assistants) don't load ("no mods on this server"). The launcher, `kiln.log` and support reports now say to remove `shroudlink_core.dll` from the game folder, and Kiln then runs the mods. Keep the client addon on: it draws the MODS tab. Before, the hint named the wrong files.

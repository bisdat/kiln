# Kiln 0.2.0-dev.29.12

A patch for 0.2.0-dev.29.11: Kiln works with a game folder that is a link again, mods for EMF 0.6.14 start (EMF's Lua mod among them, and with it every Lua mod), Kiln's windows no longer take stray clicks from play or lose the cursor after a hitch, and support reports name the game's own Steam DLL. The SDK stays at 0.2.0-dev.29.11. Everything else is as in 0.2.0-dev.29.11.

## Fixed

- **A game folder that is a link or junction works again.** When the game folder itself is a link to where the game really is (a Steam library that was moved often is), the launcher refused the profile: "the active profile changed and cannot be applied: …: symlinks are not allowed". The game folder, Kiln's data folder and a Library entry may now be links themselves; a link inside them (`mods`, `kiln` and so on) is still refused. The Engines page also showed ShroudForge with "invalid game path" and "No ShroudForge runtime report yet" for such a folder while its mods ran; Kiln's ShroudForge plugin now accepts it and, when a game folder really is unusable, says why.
- **Mods for EMF 0.6.14 start on Kiln.** EMF 0.6.13 and 0.6.14 grew EMF's API to version 46, and mods built with them (EMF's own Lua mod 1.39, Night Raids 1.2, Villager Jobs 1.5) stayed off on Kiln's older one: "this mod was built for EMF API v46; the core is v42". With EMF 0.6.14's Lua mod installed, no Lua mod ran. Kiln now serves EMF's API v46 (EMF 0.6.14). The seven functions EMF added in 0.6.13 and 0.6.14 (the game's own permissions of a player, breaking player-built blocks, villager moves) are not on Kiln yet: they answer as EMF documents when a feature isn't there, and kiln.log names each one a mod calls, once. So on Kiln, Night Raids' raiders don't break walls yet, and Villager Jobs lets only EMF's admins give jobs, not every player the game allows to kick and ban. (GitHub #43; thanks to EMF's maintainer for the list.)
- **Kiln's windows take no clicks from play.** While you play, the game keeps its cursor in the middle of the screen. A click you made just before a Kiln window opened (a mod's window on its key, Kiln's menu), or every click of a hitch that held the frame back, reached the new window there and could press its Close button or another button in the middle. A window that opens now only takes clicks made while it is open.
- **The cursor in Kiln's windows no longer jumps after a hitch.** After a frame that took longer than a quarter of a second, Kiln's cursor jumped by the mouse's raw motion and back, and a click at that moment could land where the cursor never was. It now stays where Windows puts it.

## Changed

- **Support reports name the game's own Steam DLL.** `steam_api64.dll` in the game folder was listed as "an unknown DLL". Reports now call it Steam's own Steamworks DLL.

## Mod authors

- 0.2.0-dev.29.12 ships the launcher and the runtime only; keep using the 0.2.0-dev.29.11 SDK (mod API 0.2.5).
- EMF mod authors: Kiln serves EmfApi v46 (1144 bytes; v42's was 1088). `player_permissions`, `break_blocks`, `block_at`, `find_wall`, `villager_move`, `villager_move_cancel` and `villager_moving` answer EMF's documented failure; see `docs/kiln/emf-parity.md`. Not yet run in a lab or a game: EMF 0.6.14's own Lua 1.39, Night Raids 1.2 and Villager Jobs 1.5.2 on Kiln.

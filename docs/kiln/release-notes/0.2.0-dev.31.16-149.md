# Kiln 0.2.0-dev.31.16, mod API 0.2.23 (issue 149 part; work-cm merges this file)

## Players

- **Mod windows that dock stay together.** When a mod docks its window to another mod's, for example Grimoire beside Better Spells, dragging or resizing either one moves the other with it in the same frame, and the pair stays on the screen. Hold Shift while dragging to move one alone; drop it next to the other again to dock it back. Opening both with one key no longer shows one at the wrong place first (#149). Thanks Fuzen777.

## Modders

- **Window docking across mods (#149).** `UiWindowOptions.AcceptDock`, `Ui.FindWindow(modId, placementId)` (a `UiWindowHandle`: `Available`, `Open`, `Placement`), `UiWindow.DockTo(handle, DockSide, offset)`, `Undock()`, `DockedTo` and `DockChanged` (`UiDockChange`: `DockedTo`, `Side`, `Offset`, `ByPlayer`). Kiln keeps docked windows together on the render thread in the same frame (drag, shared-edge resize, `MoveTo` of either), inside the viewport, with Shift to drag one alone, a 16 px snap back, and a docked window waiting up to 250 ms for a target opened by the same key press. Both sides opt in; a handle is a name, so a reloaded target is docked to again. `UiDraw.WindowMovedByUser` / `WindowResizedByUser` tell the player's drag or resize of the current window this frame. Modifier keys in a draw were already there: `UiDraw.HeldMods` (ImGui's Ctrl/Shift/Alt this frame); its docs now say so. Test kit: `KilnHarness.UiPlacement.FrameWindows()` and `PlayerDrags`. Samples: `DockBook` and `DockNotes`. Native: kiln.ui `window_state` (size-guarded tail at 1088). Thanks Fuzen777.

## Not yet seen in a real game

- Dragging and resizing docked windows in the game (which window's edge the pointer takes where two touch, how it feels), Shift with the game's input, two real mods opening on one key press, the samples. Kiln.Ui's docking is tested over a model of ImGui's windows, and ImGui's own drag and resize with Kiln's placement order in kiln.ui's headless host tests.

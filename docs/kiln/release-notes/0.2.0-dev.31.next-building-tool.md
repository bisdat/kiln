# Building tools: brush picker, brush preview, tool pools at the next start

## Players and server admins

- **Picking another brush keeps your tool.** With a mod's building tool (a `BuildingToolBlock`, for example a rubble tool), choosing another brush size in the picker turned the tool in your hand into the vanilla Overgrowth Tool. The brush you pick takes the tool's slot on the actionbar, as a vanilla Overgrowth shape does, and Kiln only recognised the tool itself there: from the first pick on, the picker listed the vanilla Overgrowth shapes and the next pick gave you the vanilla tool. The picker now keeps the tool's own brushes whichever of them is in the slot, also after you save and reload, in single player and on a dedicated server. If an earlier pick already left the vanilla Overgrowth Tool in that slot, put the mod's tool back there (craft it again if it is gone). Thanks to SonjaNemitz for the report and the traces (kiln#153).
- **A brush's preview matches its size more closely.** Every brush showed the small vanilla shape's preview at the cursor, whatever its size. The game draws that preview as one fixed effect per vanilla size (0.5, 1.5 and 2.5 m), so a brush now shows the one nearest its radius: below 1 m the small one, below 2 m the medium one, from 2 m the big one. Kiln still gives the stroke the brush's exact radius (kiln#153).
- **A building tool that adds terrain works from the second start.** A tool with an Add action needs a tool material pool, which is new to the game at the first start and kept for the next one. At that next start Kiln read the kept pool back as the wrong kind of pool and refused it ("unknown field entries"), at every start, so the tool and its brushes never came into the game and its recipe had no item ("output item ... not found"). The pool is now read back as a tool pool, also the one a 0.2.0-dev.31.14 to 31.19 game already kept, so such a tool works from the first start after the update. On a server, the server and every player's game each keep the pool for their own next start: a player who joins in their game's first start with the tool is refused at the join (the message names the pool) and gets in after starting the game once more. Thanks to SonjaNemitz, who found the exact line (kiln#152).

## Modders

- No mod API change.
- kiln.worldtables: a replayed pool envelope is read back from its own section (`toolMaterialPools` when its canonical lists `entries`, `buildingMaterialPools` otherwise), the same way the envelope is read; define errors of a tool pool name it `toolMaterialPool`.
- kiln-tools brush picker: the frame is the held family's when its selected hotbar item is the root or any of its brushes (all 64, not only the 16 the picker lists) and the resolved item is that same item. The trace's `not selected` now means the slot holds neither; `not resolved` means the resolved item differs from the slot's.
- Each brush item now also sets `equipment.cursorVfx` to `item:Building_Overgrowth_Shape_Small`, `_Medium` or `_Big`, the vanilla shape nearest its radius. Its base stays `Building_Overgrowth_Shape_Small`. The ref is part of the brush's definition only: a mod's own content layer on its brush item's `equipment.cursorVfx` applies over it.
- The game's brush query has three other callers (`0xd180a0`, `0xd20190`, `0xd6aa05`). None of them is reachable on client 26430625, so they stay unadapted and no other brush list exists (`docs/re/building.md` 1.2.2, with the pick's path from the client to the host).
- `test-tool-content.sh` with extracted inputs takes two more files, `shape-medium.bin` and `shape-big.bin` (`extract_tool_content_inputs.py` writes them).

## Not yet seen in a real game

- Picking each brush of a family in turn, in single player and on a dedicated server, and with a brush in the slot after a save and reload. Read statically (server 26430253, client 26430625): the host checks only that the picked item exists and carries one of four item flags (a brush's `IsTerraformer` among them), so a dedicated server puts the family brush in the slot as single player does, which the 31.19 trace showed in single player (strokes used the picked brush).
- The nearest-size preview of each brush, and whether the stroke's visible size follows the radius (the trace shows the radius reaching the game's terraform).
- A tool with an Add action across two starts, its recipe and its first stroke.

# Kiln Rust ABI generator

Run from the repository root through the project's build limiter:

```sh
python3 -I tools/sfi/abigen/generate.py
python3 -I tools/sfi/abigen/generate.py --check
python3 -I tools/sfi/abigen/test_abigen.py
```

Requires Python 3 (stdlib only) and installed clang supporting
`--target=x86_64-pc-windows-msvc`. `--root` selects a repository; `--clang`
selects its clang executable. Set `TMPDIR` to your assigned scratch directory.
Generation needs no Windows SDK and never executes a Windows binary.

Each header is compiled **independently**, with exactly its declared includes:
`native/core/abi/kiln_api.h` and every sorted `services/*.h`. Private C++ `.hpp`
helpers are not part of this C ABI. Clang JSON AST supplies declarations and
function-pointer signatures. Preprocessing supplies only active macro definitions,
with defining-header ownership; included constants are not emitted twice. String
literal bytes come directly from compiled LLVM constants, preserving byte escapes,
plain UTF-8, embedded NULs and the final C terminator without Unicode re-encoding. A small compiled probe supplies Windows x64
`sizeof`, `_Alignof`, and each field's `offsetof` as LLVM IR constants; a second
C static-assert probe checks those values against the header. Rust compile-time
assertions independently check all generated records and fields against them,
including inline union members. No C layout rules are guessed in Python.

Generated source is committed under `crates/sfi/kiln-abi`. The crate is MIT,
`no_std`, dependency-free, and has nullable function-pointer slots. Its ABI is
Windows x64; the layout assertions also run on a 64-bit host for offline tests.
Shared root declarations are generated once and re-exported by the crate root.
Each service has a module under `kiln_abi::services::kiln_<name>`. Included service
types are re-exported, never duplicated. This intentionally does **not** flatten
all service names: `kiln_creatures.h` and `kiln_rules.h` currently define different
`KilnRulesStatus` records. The manifest records every cross-header name collision,
including field types and layout, so future co-inclusion hazards remain visible.

`abi-manifest.json` contains input SHA-256 hashes and a sorted output-path-to-SHA-256
map of the exact UTF-8 generated bytes (excluding the manifest itself), measured
layouts and a complete
inventory of function-like macros and static inline helpers not emitted as FFI
functions. Function-like C macros (`KILN_SLOT_ID`, `KILN_BOOT_INFO_HAS`, etc.) are
not constants or DLL exports; consumers must implement their documented operation
rather than attempt to link them. Object-like numeric, UTF-8 string, and byte-frame
constants are emitted. String constants include a trailing NUL, but `KilnStr.len`
must exclude it. Rust-only keyword field `self` becomes `self_`; ordinary keywords
use raw identifiers. Bitfields, unknown attributes/conventions, unsupported types
and non-value macros fail closed instead of being represented as opaque pointers.

`--check` recompiles all probes, regenerates in memory, and compares every expected
file. Changed input bytes (even a comment) change the manifest. Changed output and
obsolete service modules fail too. It never modifies the tree. Generation never
deletes obsolete output files; remove them explicitly after reviewing the drift.
Absolute source paths, AST ids, timestamps and compiler-version strings are not
written into generated output.

## Verification

Generator tests cover const/pointer nesting, arrays, union fields, callback
signatures, nullable slots, object constants (including all 256 string byte values,
LLVM doubled-backslash escapes and Windows paths), negative enums, opaque pointer types,
Rust-only keywords, header self-containment, shared type identity, conflicting C
tags, deterministic output, and input/output drift. `kiln-abi/tests/ffi.rs` calls a
real Rust C callback and checks shared header identity. Every record's complete
layout is also a compile-time assertion, not just a selected smoke-test size.

Before the separate `crates/sfi` workspace is integrated, copy this crate into an
assigned scratch-only workspace and test the copy. Do not modify the repository's
existing root workspace or add a temporary `[workspace]` table to the crate.
After integration, use its pinned toolchain and lockfile. Cross-target `cargo
check --target x86_64-pc-windows-msvc` compiles the same layout assertions without
requiring Wine. Cross-compilation proves layout, not runtime service semantics.
